## 真实宿主与本地假接口

通过本机 `dsh-sandbox-test` 启动器使用 alpha，安装本次构建快照；另起临时 3196 端口，覆盖插件状态文件并注册虚构工具和动态段落，使用官方 sessionController 创建会话、发送消息及等待 Agent 空闲。临时实例退出后清理它自己的进程；没有停止原先的 3182 人工测试实例。

夹具阻止对 localhost/127.0.0.1 之外的 HTTP 访问，只使用虚构凭据和消息。以下一轮验证共记录 **12 个本地 HTTP 模型请求（包含辅助请求），外部模型调用为 0**：

1. 启用预设并发送工具调用，由宿主执行虚构工具后继续生成。两个 step 的动态 provider 各执行一次，没有因注入再组装；实际 system 正文包含宿主 waterfall 的最终新增内容。
2. `when` 拒绝的虚构工具没有进入实际请求 schemas。
3. 自定义一个动态段落并禁用另一个段落，两个 step 均使用修改；其他宿主段落继续继承。模型变量展开正确，缺失来源的自定义段落没有被强行注入。
4. 工作台草稿 API 解析同一组段落配置；旧整篇模板覆盖分段配置，不重复叠加。
5. 注册宿主 `complete` 段落后，实际请求使用它作为唯一默认系统正文，未把其他已注册段落重新拼回去。

开始时曾误用旧安装快照，计数显示重复组装；更新 alpha 快照后上述验证通过。临时结果和夹具位于忽略的 `.test-data/dsh-sections-runtime/`，不纳入提交或发布包。

## 后续配置加载回归修复

人工反馈工作台不能加载配置后，检查原先持续运行的 3182 实例：配置 API 返回 200，但静态 `editor.js` 已从磁盘读取新内容，进程内仍是旧路由，新增的 `dsh-template-editor.js` 与共享段落模块返回 404。原先的静态 import 因此阻止整个入口运行，未发生预设数据丢失。

入口改为受保护的动态 import，新增面板不可用时只禁用其编辑，不阻断配置和其他预设操作。新增完整启动回归模拟面板模块 404，确认已有预设、会话设置和提示词列表仍加载成功，并且不会因此写入或清空配置。

重新安装快照并重启 3182 后，实际遍历工作台 10 个模块依赖，均返回 200 与 JavaScript MIME；配置 API 和系统模板读取恢复正常。这是实际 HTTP 验证，不等同于浏览器截图检查。

修复后入口语法检查通过，完整自动回归为 612 项全部通过。
