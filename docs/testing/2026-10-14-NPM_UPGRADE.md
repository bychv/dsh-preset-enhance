# npm 0.3.5 到 0.3.6 升级验证

日期：2026-10-14。宿主：alpha 槽位 npm DSH 0.2.1-alpha.2。使用独立 `preset-npm-upgrade` profile、临时端口及虚构预设；没有覆盖日常 DSH 或 alpha 的 web profile。

## 升级路径

先通过沙盒隔离环境的 DSH 插件 CLI，从官方 npm registry 安装 `dsh-preset-enhance@0.3.5-alpha.1`，启动后保存虚构预设。停止临时宿主后保留当前选择、会话绑定与预填充设置，再通过相同 CLI 从 npm 升级至 `0.3.6-alpha.1`。没有使用源码快照、file 依赖或正文包 override。

## 结果

- profile 顶层依赖和选中的第三方 bundle 均只有原主包入口；正文包自动作为精确版本依赖安装，两个运行包实际版本均为 `0.3.6-alpha.1`。
- 升级与重启后，预设状态文件 SHA-256 不变，所选预设、会话绑定、预填充设置及已保存的规则保持。
- 真实 Edge 中，原主包详情页显示两个运行条目，正文包只加载一份；工作台正文开关可操作且默认关闭。
- 使用与原生插件管理器相同的公开启停操作停用正文条目，状态立即变为不可用；重启后停用状态仍保留，预设状态文件仍未改变。
- alpha web profile 的原预设状态文件哈希未变。未调用模型 API，临时宿主及浏览器已关闭。

## 边界

旧 npm 包的 engines.dsh 未包含 `0.2.1-alpha.2`，但在本次宿主中实际启动成功；新包声明 `>=0.2.1-0 <0.2.2`，覆盖该宿主。此项验证聚焦 npm 下载、依赖装配、配置保留和启停重启，不代替正文渲染、GenUI 或真实模型工具续轮测试。

本次启动失败和浏览器重试来自测试辅助插件缺少独立包身份，以及首次引导弹窗的异步关闭；修正夹具后完整升级流程通过，没有发现需要修改发布包的问题。
