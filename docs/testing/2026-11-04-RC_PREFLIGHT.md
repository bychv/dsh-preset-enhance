# 0.3.7 RC 发版前自检

目标版本为 **0.3.7-rc.1**。本次未修改包版本、推送、创建 Release 或发布 npm。RC 更新记录应相对 **0.3.6-rc.1**，不能只写 alpha.1 之后的改动。

## 相对上一 RC 的功能范围

- 支持 DSH 0.2.2，保留 0.2.1；调整工具准入、作用域与当前模型读取。
- DSH 系统提示词按模式分段编辑、禁用与恢复；兼容旧整篇模板，并复用真实请求本轮组装。
- 可选实验性 SPreset 工具注册与输出调用消费，使用受限脚本环境；不等于完整酒馆脚本运行时。
- 两个编辑器支持条目上下文图片和文件、粘贴/拖入、预览与移除；分享包按内容摘要去重资源，资源库复制保留附件。
- 预填充按实际末条内容判断，提供强制启用与动态预填充；内置格式提示词对齐 V4.1 Flash，保留旧格式解析兜底。
- 修复系统模板模块缺失导致配置加载中断，以及附件分享校验、保存容量和同一预设并发编辑覆盖。

以上是核对范围，不是按开发提交逐条罗列的发布日志。

## 本次发现与修复

图片入库接口只接受输入内容，不接受任意模型消息块。原先传整条消息会让宿主把推理/工具调用误作图片处理。现仅将图片批量交给宿主，按原位置恢复，其他块原样保留，并检查返回数量和类型。文件数量仅统计入库成功的项。

强制预填充候选现在跳过携带附件的助手条目，避免移动不可续写的消息并遮蔽此前有效的文本前缀。

## 第二轮独立审计（宿主 + 前端）

在既有结论上再开两条独立审计线，逐条复核宿主 0.2.1-rc.4 与 0.2.2-alpha.3 源码，并用构建产物复现关键路径。发现并已修复：

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| BLOCKER | 上下文文件挂在 system/assistant 条目：宿主 Messages 序列化器对非 user 消息中的图片抛 `UNSUPPORTED_CONTENT`，整轮请求失败；Chat 适配器则静默降级成文字占位 | 校验层拒绝非 user 条目携带上下文文件（保存、导入、编译同一条规则）；两个编辑器在添加时直接挡住并说明先把角色改为 user；材料化再兜一层：非 user 消息里的身份块跳过并告警 |
| HIGH | 单条 24 项超过宿主单消息入库上限 20，21–24 张会被整批拒绝 | 按 20 张分批调用 `admitPromptContent` 并合并结果，超批给出告警 |
| HIGH | 内联兜底身份 `preset:<hash>` 会让宿主 `imageHostPath` 抛 `INVALID_ATTACHMENT_REF`，整轮变 TRANSPORT 失败 | 身份改为 `sha256:<hash>`；`imageAccessOf` 对无法识别的引用 try/catch 返回 undefined |
| HIGH | 无聚合体积上限，state.json 每次事务整文件读写 | 新增每预设 24 MiB 上下文字节上限（保存/导入都校验）；编辑器同步显示 `N 项 / X MiB` 并在添加时按剩余额度拒绝 |
| HIGH | 工作台批量读取中切换预设，附件可能写进另一预设的同名条目 | 守卫改为对象身份比较，并在载入草稿/重载时自增令牌 |
| MED | 内联 variantId 污染 Files 上传索引，导致历史 file_id 复用失效 | 与上面身份修改同批修正（`sha256:<hash>`） |
| MED | 模态检查晚于入库，纯文本模型会白跑一次附件存储 | 先按编译结果统计预设图片并做模态检查，再做材料化 |
| MED | SPreset 复制为模板丢附件、结构化 tab 输出全量 base64 | 生产端带上 `contextFiles`；模板 INSPECTOR 增加只读列表；结构化视图把 data 替换为大小摘要 |
| MED | 预览不校验像素，压缩炸弹可拖垮标签页 | 新增 4000 万像素上限，超限拒绝并降级为徽标；图片加 `decoding="async"`；canvas 缩略图未做 |

独立验证：`npm run verify` 通过，**639/639** 测试；新增用例覆盖非 user 角色拒绝、非 user 消息跳过、21 张分批入库、24 MiB 预算、Messages 适配保留非文本块、编辑器竞态丢弃与预算恢复。

剩余已知缺口（不阻塞 RC，发版说明中注明）：

- 编辑器载入分享包时把资产字节展开进草稿，state 中会同时存在草稿内联 data 与 `sharePackage.extensions.assets` 两份字节（后续应改成只读展示层缓存，或在保存前收敛回 asset）。
- 预览缩略图仍用原始 data URL，未做 canvas 降采样；超大但未超 4000 万像素的图片仍会整张解码。
- 材料化使用事务外读到的预设快照，保存恰好发生在读取与事务之间的极窄窗口内可能发出旧字节（未做内容摘要校验）。
- 请求预览与 Raw 不做材料化，上下文文件在预览里显示为身份块而非图片。

## 真实浏览器视觉回归

用无头 Edge 156 经 CDP 直接驱动沙盒页面（无需额外依赖），创建临时探针预设（虚构图片/文件字节）后逐步操作，结束后删除该预设：

| 场景 | 结果 |
| --- | --- |
| 工作台加载 | 页面完整渲染，无 console 异常；仅 favicon 404 |
| 工作台附件预览 | 选 user 条目后显示 `4 / 24 项 · 29.9 KiB / 24.00 MiB`，缩略图 `naturalWidth` 为真实像素（64×40 / 96×64），`decoding=async` |
| 页面粘贴事件 | 通过 `DataTransfer` + `ClipboardEvent` 粘贴 PNG：卡片数 +1、合计字节随之更新、提示显示"已附加 1 项 · 合计 …" |
| 灯箱 | 点击缩略图弹出 `<dialog>`，大图按原尺寸解码，右上角关闭按钮可用 |
| 保存 | 点击「保存预设」返回"预设已保存"，宿主接受含附件的草稿 |
| 角色守卫 | 条目改为 system 后粘贴被拦："上下文文件只能加在 user 角色条目上（当前 system）"；保存被宿主拒绝并显示同一原因 |
| SPreset 附件区 | 同一预设显示只读/可编辑附件区、`4 / 24 项`、缩略图真实渲染；提示词链徽标显示「图 ×4」「文件」 |
| CSP | `data:` 缩略图在真实浏览器中渲染成功，灯箱与粘贴路径均未被 CSP 阻断 |

视觉回归中发现并修复一处缺陷：粘贴"只有 PNG 签名、无法解码"的字节时，编辑器仍把它存进草稿并渲染成破图。现在两个编辑器在 `readImageSize` 失败时直接跳过并提示"无法解码为有效图片"。

## 剩余边界与发版操作

已补充上表所列的无头 Edge 页面与截图检查；粘贴通过脚本派发事件，未验证系统剪贴板、原生文件选择器与拖入文件的完整交互。插件管理器完整热重载、真实模型续写和图片上传后的模型回答仍未验证。附件入库成功不能替代两种协议的真实模型端到端验证；旧版 0.2.1 的证据沿用已有记录，没有重跑完整 Web。重新安装后仍需确认运行进程已加载最新快照，不能只依据磁盘文件判断。

正式发版时统一主包、正文包、兼容 bundle 和精确依赖为 0.3.7-rc.1，构建实际 tarball 并复核。按既有流程先 GitHub Release，再正文包、主包 npm `next`；`latest` 不自动移动。本次清单检查使用当前 alpha.1 版本，不宣称 RC 包已发布或可下载。
