# 外部模板注册与插件组合接口方案

状态：总体设计草案；T01/T02 模板注册与选用注入已实现，实际使用以 [模板 API 文档](../api/TEMPLATE_API.md) 为准。序列处理、渲染和脚本接口仍未实现。任务进度见 [实施索引](PACKAGE_IMPLEMENTATION_TASKS.md)。配合 [显示分包方案](DISPLAY_REGEX_PACKAGE_PLAN.md)，渲染模板随显示包实现，不为此新建通用插件框架。

## 职责分开，按引用组合

| 提供方 | 管理内容 | 不接管的内容 |
| --- | --- | --- |
| 预设根包 | 提示词模板目录、用户选用记录、顺序表、序列处理链、编译与请求注入 | HTML 渲染、变量更新模型、外部插件存储 |
| 显示包 | 渲染模板目录、组件实例、外观与交互状态、受控动作路由 | 全局预设选择、提示词隐式注入、变量真值 |
| 变量插件 | 变量快照、修订、重生成和历史依赖 | 正文 DOM、选项栏样式、预设顺序表 |
| 未来脚本运行时 | 脚本实例、事件处理、任务取消及受限 API 适配 | 宿主注入顺序、变量真值、渲染容器和其他插件内部存储 |
| 其他功能插件 | 注册自己拥有的模板、变量或动作能力 | 直接改写其他插件的模板、启停状态和内部文件 |

提示词模板与渲染模板是两种契约，分别注册到对应服务。可以共用 providerId 和关联引用，但不把 HTML、CSS 或动作代码写进提示词模板字段，也不要求只提供提示词的插件依赖显示包。

注册只让模板进入可选目录。用户加入顺序表并启用后，根包才通过现有 compilePreset 编译注入。外部插件不再另外监听 llm/stream 插入同一段提示词，避免重复注入和依赖插件加载顺序。

## 提示词模板注册接口

服务名暂定 presetTemplates，接口版本为 1，通过宿主 Cordis 服务提供。只有确实使用模板的子功能依赖此服务；提供者的其他功能可独立运行。外部插件使用公开契约，不 import 根包内部 lib、不读写 state.json；浏览器只读取目录和执行用户的选用操作，不能注册带代码的生产者。

```ts
interface PromptTemplateV1 {
  id: string;
  version: string;
  title: string;
  description?: string;
  role: 'system' | 'user' | 'assistant';
  content: string;
  defaults?: {
    placement: 'beforeHistory' | 'afterHistory' | 'depth';
    depth?: number;
    order?: number;
  };
}

interface PresetTemplatesV1 {
  readonly contractVersion: 1;
  register(ownerContext: PluginContext, definition: {
    providerId: string;
    title: string;
    templates: PromptTemplateV1[];
  }): { update(templates: PromptTemplateV1[]): void; dispose(): void };
  list(): TemplateCatalogSnapshot;
  subscribe(listener: (catalogRevision: number) => void): () => void;
}
```

这里的类型是拟议契约，宿主上下文类型与目录 DTO 在实现时补齐。注册函数为整个注册批次绑定 ownerContext.effect 清理；返回的 dispose 同样幂等。根包停止时清理全部注册，提供者按依赖生命周期重新注册，不能将模块级全局 Map 当成持久状态。

模板身份为 providerId + id + version。不同提供者同名不冲突；另一个活跃实例占用相同 providerId 时明确报错，不覆盖旧注册。同版本内容必须相同，修改内容需新版本；update 校验整批后原子替换目录。清理使用注册实例身份，旧实例迟到的 dispose 不能删掉热重载后的新注册。

第一版只注册静态模板与位置建议，不接收任意请求回调、模型任务或可执行表达式。模板内容可以使用已有预设宏，但仅在实际启用并参与编译时执行；浏览目录、预览和注册不能修改真实宏变量。字段、大小、重复 ID 和角色在注册时统一校验，失败不影响已生效目录。

## 用户选用、顺序与保存

工作台在模板资源区提供“插件模板”，标明来源、版本及可用状态，与用户自己的资源库分开。加入后是普通顺序表条目，可开关和调整位置；插件只提供插入位置建议，用户选定的最终顺序优先。

引用信息保存在 extensions['dsh-preset-enhance'].templateBindings，以预设 prompt identifier 关联，避免外部模板 ID 与 chatHistory 等保留标记冲突。例如：

```json
{
  "templateBindings": {
    "prompt-local-001": {
      "providerId": "example.display",
      "templateId": "input-guidance",
      "templateVersion": "1.0.0",
      "mode": "linked"
    }
  }
}
```

关联条目同时保存用户接受的模板文本快照，供预览、导出和差异比较；启用开关只保留在现有顺序表，避免另建一套相互矛盾的 enabled。引用与模板文本同时保存，沿用现有事务、revision、自动保存、预设锁定和会话绑定逻辑。修改全局有效预设仍按现有规则影响当前会话，显式绑定其他预设的会话不跟随。

外部关联模板的正文默认只读，用户可“复制为本地模板”解除关联后编辑；顺序和开关始终由用户控制。不能把用户编辑悄悄回写到提供者，也不能因插件更新覆盖用户的本地副本。

默认锁定选用的版本。出现新版本时提示查看差异并更新；不根据加载先后自动选择新版。相同引用重复加入时默认定位已有条目，需要用户明确选择才创建第二个实例。组合配置也复用已有实例，不能叠加重复的格式要求。

## 编译和失效边界

请求开始时固定一份模板目录快照，解析当前预设的关联条目，生成临时的有效预设，再走现有编译器。原预设文件与历史消息不变；后续目录更新只影响下一次请求，不能改写正在进行的请求。

缓存键必须包含所选模板的版本、内容摘要和可用状态；模板更新、卸载及重装后不能复用过期编译结果。只纳入本次使用的模板，避免无关插件刷新目录使所有会话失效。预览与实际请求使用同一解析入口，预览不能假装注入不可用模板。

| 状态 | 行为 |
| --- | --- |
| 预设注入关闭或顺序表条目关闭 | 不注入该模板 |
| 外部模板有效且用户已启用 | 按顺序、角色与深度统一编译 |
| 插件卸载、模板撤回、锁定版本不再提供 | 保留引用、快照和顺序位置，标为不可用并跳过，明确提示 |
| 用户选择脱离插件继续使用 | 复制为本地条目；含外部变量或动作依赖时提示这些能力不能随文本复制 |
| 模板位于 chatHistory 之后 | 保留其位置，不移动到请求开头 |
| 最终条目为 assistant | 沿用既有预填充判断、协议限制与提示，不由注册接口改变连接 |

不以“缺少模板”为理由回退到某个随机版本或静默注入旧快照。热重载开始前已固定的请求可以按快照完成，后续请求依照最新可用状态。模板提供者不需要处理工具调用重试，也不能另行追加工具后预填充；这些仍由根包统一处理。

单文件分享保留关联元数据和用户接受的模板快照，不包含外部插件代码、运行时变量或凭据。导入时检查依赖并列出缺失项；用户可安装对应插件恢复关联，或显式转为本地文本。未知字段保持无损，导入不会自动安装或执行外部插件。

## 提示词序列处理接口

另提供可选服务 promptSequence，供其他插件处理实际发送前的提示词序列。它与 presetTemplates 分工不同：模板注册负责提供可选内容，序列处理器负责对本次请求里的内容做组合、替换、删减或排序。两者不互相代替，处理器也不能直接改写保存的预设和聊天历史。

第一版只开放一个固定阶段，避免多个前后钩子导致执行顺序难以判断：

```text
确定有效预设、模板和变量快照
  → 现有顺序表、宏、历史/深度注入与工具后前缀处理
  → 现有提示词侧正则
  → 外部提示词序列处理器（串行）
  → 最终结构校验、重新判断 assistant 预填充
  → Messages/Chat 协议适配与发送
```

此阶段输入已完成宏展开，处理器返回的文本按字面内容使用，不再次运行宏和正则，避免 setvar 重复执行或处理链递归。需要改变宏展开前的模板内容时走模板注册与选用流程；以后确有需要再增设命名清晰的编译前阶段，不混用当前接口。

### 注册和调用约定

```ts
interface PromptSequenceV1 {
  readonly contractVersion: 1;
  register(ownerContext: PluginContext, definition: {
    providerId: string;
    id: string;
    version: string;
    title: string;
    capabilities: Array<'prompt.edit' | 'historyText.edit' | 'prefill.edit'>;
    process(input: ReadonlySequenceInput, context: SequenceContext):
      SequencePatch | Promise<SequencePatch>;
  }): { dispose(): void };
  list(): ProcessorCatalogSnapshot;
}
```

类型名为契约占位，具体公开 DTO 随实现补齐。输入包含本次待发送的有序消息、稳定条目 ID 和来源分类（宿主提示词、预设条目、外部注入、历史、预填充），并保留模板/消息引用。工具、图片、附件等内容使用可识别的只读块表示，不把整条多模态消息拍平成字符串。只提供处理需要的请求副本，不传连接凭据、宿主 Context 或完整会话存储。

context 包含 sessionId、分支/正文修订、有效 presetId（可为空）、当前模式、协议、调用 ID、preview/request 用途、处理器配置及 AbortSignal。变量输入只使用显式声明并在请求开始时固定的快照。处理器不得通过修改 input 原对象产生结果，返回空补丁表示不修改。

SequencePatch 首版支持 insert、replaceText、remove、move，按稳定 ID 指定目标和插入锚点；不使用容易漂移的数组下标。replaceText 可定位文本块，插入项仅允许声明角色与文本，来源和最终 ID 由根包分配。每个处理器的补丁相对于它收到的输入，整批校验成功后原子应用；后一处理器看到前一处理器的完整有效结果。

prompt.edit 可处理预设/外部注入文本及插入新文本条目；historyText.edit 是额外的历史正文副本替换能力，默认不开启；prefill.edit 用于显式修改或移除已识别的预填充。宿主系统提示词与非文本块默认只读，处理器不能伪造来源、恢复用户已关闭的系统提示词，或绕过现有工具策略。

### 启停、排序与组合

注册只增加可用处理器，用户另行启用。处理器以 providerId + id + version 引用，生命周期与模板注册一致，重复注册报错，热重载后旧句柄不能释放新实例。第一版每个有效处理链只允许同一处理器出现一次，先不支持多实例嵌套。

处理顺序保存为用户可见的列表，不依赖插件加载顺序或各插件自行争抢优先级。A 修改某段文本后，B 可以进一步修改；这是明确的顺序语义。若 B 引用的锚点已被 A 删除，则返回冲突，不能猜位置或静默追加到末尾。不建立自动拓扑排序或通用依赖调度器。

处理链有独立总开关，与预设注入分开：关闭预设注入不应隐式开启或关闭已由用户配置的序列处理。普通模式也可显式使用处理链，此时从宿主传入的请求副本开始，presetId 可为空，不额外注入预设。未启用处理链时完全沿用现有请求行为。

配置沿用根包全局/会话覆盖规则，保存有效顺序、版本、参数、能力授权和失败策略。单文件预设可携带处理链建议及参数，但导入只列出处理器依赖，不把文件中的能力需求当作授权；实际启用由用户决定。模板、处理器和脚本可在同一组合清单中按引用关联，不需要彼此导入实现模块。

### 结构保护与失败策略

历史消息身份、角色、工具调用及结果配对、图片和附件引用保持完整；第一版不支持删除/重排历史轮次或拆分工具调用组。提示词插入与移动不得进入工具调用/结果组内部。工具定义仍由工具策略接口处理，不通过序列补丁修改。

显式预填充保持尾部语义，普通插入不能悄悄把它变成中间消息；位置冲突报错，需要调整前缀时使用 prefill.edit。处理完重新计算预填充及桥接启用信息，不能沿用修改前的缓存标记；历史里原有的末尾 assistant 不因此被当成插件预填充。新增 assistant 文本成为尾部时仍遵守现有预填充提示与协议限制，Messages 模式继续使用现有降级规则。

每步都有输入/输出大小限制和耗时预算，异步处理接受请求取消信号。失败策略由用户为处理器选择 skip 或 abort：skip 保留该步之前的有效序列继续后续步骤，并显示失败原因；abort 停止本次请求发送。默认 abort，避免用户依赖的删减或替换失败后原文仍被发送。已启用但插件缺失或版本不可用也按相同策略处理，不静默略过。

普通插件回调是可信宿主代码；AbortSignal 和 Promise 超时不能强制终止同线程死循环。第三方脚本处理器必须通过未来脚本运行时的可终止隔离执行通道接入，不能借此 API 直接 eval 导入脚本。迟到结果一律丢弃，不写入缓存或状态。

### 缓存、预览与请求生命周期

请求开始时固定有效处理链、配置和所用数据快照；并发请求各持副本。编译缓存与处理器结果缓存分开：第一版不缓存外部处理结果，每个逻辑 LLM 请求在编译副本上执行一次，避免动态处理器被旧缓存绕过。工具调用之后的新一轮 LLM 请求需要重新处理；同一已准备请求的递归路由和传输重试复用处理后的副本，不能重复追加。

预览使用同一处理流程，但不提交宏变量、发送消息或写入外部状态。process 应是输入到补丁的转换，不启动独立模型任务或执行其他外部副作用；需要异步模型准备时，先通过独立生产者提交快照再读取。工作台展示处理器顺序、每步差异与警告，原始请求正文不自动写入日志。未来若加缓存，必须由处理器声明确定性并提供依赖修订，不能只按处理器版本判断。

实现时需将编译结果的最终预填充判断与协议适配留在处理链之后；宏计算先在状态副本中完成，最终处理成功才按现有修订规则提交。异步处理器不能长时间占用全局 store.transaction 写锁；发生状态冲突时明确终止或受控重建整次准备，不能在旧宏结果上再次累加。停用/热重载撤销处理器后，取消未完成调用；已完成并固定的发送副本按现有请求生命周期收尾。

最小验证覆盖：两个处理器串行组合、锚点冲突、历史工具块保护、预填充被修改后的重新识别、预览无副作用、取消/超时、插件缺失、同请求重试不重复注入，以及预设关闭时单独处理普通模式请求。此处仅是接口设计，尚未新增可调用服务。

## 变量、渲染和工具的组合

组合以小型的功能清单表达关联：提示词模板与序列处理器引用、可选的渲染模板引用、变量提供者与字段绑定、动作引用、未来可选的脚本引用，以及建议使用的已有工具分组。清单只描述组合关系，不重新定义模板、变量、工具的存储格式。

例如一个状态面板可以组合“状态输出格式提示词 + 自定义面板模板 + 变量插件快照”；一个选项栏可以组合“候选项数据 + 自定义选项栏模板 + 点击追加草稿动作”。候选项来自既有标签适配或独立生产者时，无需额外注入提示词；需要模型输出特定选项结构时，才另行提供对应的提示词模板。选项数据可以单独更新或重生成，外观模板与正文保持不变。

用户应用组合前查看各项开关；提示词注入、显示、变量任务和工具策略仍各自控制。必需依赖与可选能力需明确声明：缺少必需依赖的组合显示未就绪，可选能力缺失只降级该部分。不能因为打开一个渲染模板，就自动开启工具、启动变量模型或改变预填充配置。

组合应用由各服务验证并保存自己负责的配置，结果逐项可见；首版不实现跨插件事务。不具备全部必需能力时，不宣称整组已启用，也不自动启动模型。插件独立关闭后只停用依赖其能力的部分，用户的选择与文本保留。

后续需要将动态变量注入提示词时，增加显式的数据绑定接口：变量提供者提交带修订的会话快照，根包在请求边界读取最后已提交值。模板和变量数据分开，数据值作为字面文本或结构化 JSON 插入，不再递归解释其中的宏。渲染更新本身不改变请求；只有启用了提示词数据绑定才参与注入。首版静态注册接口不承担等待独立模型完成的职责。

## 为未来脚本系统预留的接入边界

脚本运行时作为可选的独立能力接入，不放进正则执行器、提示词编译器或 HTML 模板里。根包与显示包都不强依赖脚本运行时；未安装时仍能完成静态提示词注入、静态展示及内置选项点击。确实需要脚本的交互标为不可用，并保留配置供以后恢复。

脚本系统复用公开通道：通过 presetTemplates 提供可选提示词，通过变量提供者读取或提交状态，通过 RenderService 发布或更新视图；需要处理请求序列时，由运行时适配器注册 promptSequence 处理器，仍须用户启用并遵守固定阶段。脚本的点击处理统一注册为命名空间动作，渲染模板只引用动作 ID，不嵌入函数或任意调用字符串。脚本不能注册同名动作覆盖内置追加草稿或其他插件的处理器。

### 最小运行时契约

暂定 scriptRuntime 契约版本 1，先约定职责，不在本轮实现执行器或固定脚本语言：

| 接口 | 约定 |
| --- | --- |
| describe / capabilities | 查询运行时版本、支持的绑定范围、事件与可调用能力；宿主能力不足时明确返回不可用 |
| activate(binding, scopedApi) | 创建指定版本的脚本实例，返回可幂等释放的句柄；scopedApi 由宿主按所属会话及授权构建 |
| handle(event, signal) | 接收结构化事件，支持取消，返回可校验的数据；不取得宿主 Context 或 DOM 对象 |
| dispose | 取消任务、撤销动作注册、解除订阅及释放资源；旧实例的迟到结果不能写回 |

这是运行时适配器的接入面，不是把任意脚本当成可信 Cordis 插件。具体语言、隔离方式和资源限制留到脚本系统实施时确定；不能仅靠传入一个裁剪对象就宣称安全隔离。跨边界只传可序列化数据，文件、网络、模型调用等能力以后通过独立的受控服务按需开放。

脚本身份使用 runtimeId + scriptId + version，实例再绑定会话、分支和可选的 viewId。scope 分为 session 与 view：会话脚本不因主栏、侧栏重复显示而启动两次；视图脚本只负责该实例的交互，挂载事件不能默认启动变量重生成。切换会话不把旧脚本迁移到新会话，热重载和停用必须释放对应句柄。

### 事件与写入分开

先预留少量明确事件：正文某个版本完成、变量快照已提交、用户选择选项、视图挂载/卸载。事件名称与载荷由契约登记，不直接透传全局 window 事件。正文结束后的脚本任务不挂起正文结束信号，结果沿用组件独立更新流程。

事件携带所属会话/消息、目标修订、eventId 与来源操作标识。宿主负责同一事件重复投递的识别，写入仍用操作 ID 和修订检查防止重复生效；仅靠事件去重不能保证副作用只发生一次。变量更新引发脚本、脚本再次写变量时，需来源链和有限重入规则，避免监听自身更新形成循环。

普通事件只通知已发生的事实，不能直接修改正在编译的请求。请求副本的转换通过上文 promptSequence 固定阶段进行；若未来需要先启动模型准备数据，再单独设计显式等待策略，不让后台事件处理器直接改写 messages。序列处理继续使用请求开始时的已提交快照。

脚本读取变量快照后，向变量提供者提出带预期修订的更新；由提供者决定校验、提交与历史依赖。更新成功后再驱动组件显示，不直接调用显示层 updateVariables 冒充变量库已经保存。脚本自有状态则存在自己的会话命名空间，不混入预设宏、MVU 状态或其他脚本的存储。

用户点击事件的操作凭据由可信动作层生成，脚本只可消费该次操作允许的能力，不能通过 event.source = 'user' 自行取得发送权限。后台脚本更新选项和外观不等于用户发送消息；以后需要自动执行工作流时，另行声明并配置对应能力，不复用选项栏“点击即发送”的授权。

### 保存与组合预留

在预设命名空间预留可选 scriptBindings，与 templateBindings 并列。示例只表达引用与组合，不含可执行源码：

```json
{
  "scriptBindings": [
    {
      "id": "choice-controller",
      "runtimeId": "example.scripts",
      "scriptId": "choice-controller",
      "version": "1.0.0",
      "enabled": false,
      "scope": "session",
      "requestedCapabilities": ["variables.read", "views.update", "actions.handle"],
      "config": { "viewId": "choices" }
    }
  ]
}
```

requestedCapabilities 是能力需求清单，不是已获授权；分享文件不能替接收者授予权限。当前实现尚不认识的脚本字段按既有扩展字段规则原样保存，不执行。未来单文件格式若附带脚本资源，使用独立的资源段及版本/摘要引用，不把源码塞进 HTML 或提示词；没有运行时也应能无损导入导出，导入不会自动激活脚本。授权、密钥、任务状态与运行时变量不随预设分享。

组合清单可声明脚本是必需还是可选。以选项栏为例：模板负责外观，变量或模型提供候选项，脚本负责筛选/联动及处理已授权的动作。脚本停用后保留最后候选项快照，停用依赖脚本的按钮；内置追加草稿功能仍可用。整个流程不要求脚本控制正文渲染或宿主输入框。

旧预设的助手脚本以后可通过专门适配层接入这套 API，逐项映射变量、事件和动作。预留接入空间不表示支持 parent.document、任意修改历史或所有酒馆脚本；历史修复/撤销仍需单独的历史修改服务，不能借脚本桥绕过。

本阶段只把可选引用、稳定身份和能力查询留在契约里，不做通用脚本市场、调度平台或完整事件总线。以后接入时重点验证重复挂载、卸载后迟到写入、事件循环、跨会话路由以及无运行时的降级。

## 最小实施顺序

1. 在根包实现静态注册目录、生命周期清理和公开类型；使用两个虚拟提供者验证同名隔离及卸载重载。
2. 工作台加入插件模板区域、选用与来源引用，接入统一编译、预览、缓存和自动保存。
3. 验证历史之后注入、assistant 预填充、模板版本更换、提供者缺失及分享后恢复。
4. 在根包加入独立的序列处理器注册与固定处理阶段，先验证串行组合、结构保护、预览和请求生命周期，不依赖显示包。
5. 显示包落地后实现独立渲染模板目录和可定制选项栏，再补组合清单与变量绑定；无需先搭建通用服务总线。
6. 预留脚本引用与能力查询边界，暂不执行脚本；未来运行时通过同一模板、序列、变量、视图和动作接口接入。

分阶段验证各自接口边界，不为方案阶段运行完整沙盒或调用真实模型。当前仅模板注册目录可调用，其余服务和行为依照实施索引推进。
