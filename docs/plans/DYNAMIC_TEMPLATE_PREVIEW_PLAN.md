# 动态提示词模板与请求预览实施方案

状态：next-ver 已实现 D01–D04 的基础功能，尚未发版。可调用接口、示例及使用边界见 [模板 API](../api/TEMPLATE_API.md)，总体边界见 [插件接口方案](PLUGIN_TEMPLATE_CONTRACT_PLAN.md)。下文保留设计依据；当前实现范围与验证见文末。

目标：在点击发送后，根据本轮用户消息和会话数据生成模板正文；工作台可调试这一过程，并查看每次实际发出的消息。动态解析不依赖独立显示包或提示词序列处理链先落地。

## 一、当前缺口与实现原则

目前模板目录只保存静态 content，compilePreset 在请求时展开宏，已支持 lastusermessage 等值；复杂检索或异步计算没有接入点。实际发送在 src/index.mts 的 injectStream 中编译并缓存，而预览直接调用 compilePreset，两者后续处理不同。

现有预览还有三处需要一起调整：

- previewHistory 主要从 deriveMessages 读取历史，不等同于宿主最终提供给 llm/stream 的完整输入。
- “查看最近实际注入”读取的是编译缓存，未覆盖适配器序列化、Messages 转换、工具过滤和预填充桥接后的最终请求。
- refreshPrefillWarning 会调用 preview 接口。不能因此在加载预设或切换面板时反复执行动态提供者。

采用“异步准备一次、同步编译一次、发送前记录一次”的路径。静态预设保持现有快速路径；不增加轮询、每次编辑自动解析或全目录重新计算。

## 二、模板定义与运行时正文分开

继续由 presetTemplates 管理可选模板。普通条目和酒馆 marker 关联均支持动态正文，用户仍需选用、保存并启用条目；DSH 系统提示词控制项不可接管；chatHistory 已追加受限的 history-patches 接口，见模板 API。

增加可选能力 dynamicTemplatesV1。公开目录只新增可序列化的动态描述，例如解析器 ID、需要本轮用户消息还是完整历史；宿主回调通过注册时的独立 runtime 参数提供，不放进 list()、HTTP 目录或导出文件。提供者先检查能力，旧的静态 register 调用继续可用。这里是拟议约定，实施时补充公开类型。

模板 id/version 固定的是模板文本、动态槽位、解析器版本和输入声明；每次生成的正文不是新的模板版本。运行时数据变化不会触发目录 update、重新接受版本或全局目录广播。解析器行为升级需要对应的新模板版本，不能用函数序列化或函数源码哈希判断版本。

动态绑定使用可辨别的 mode，例如 linked-dynamic，保留 providerId、templateId、templateVersion、fingerprint，以及用户配置和失败策略。现有版本只认可 linked，遇到新的 mode 会跳过并提示，避免降级后把动态模板说明或旧结果当正文发送。单文件分享保存定义快照与引用，不保存本轮动态结果、回调或会话数据。

### 输入和输出

解析器收到只读的本次调用上下文：

| 输入 | 约定 |
| --- | --- |
| 会话与请求身份 | sessionId、分支/历史修订、逻辑请求 ID、工具续轮序号；预览可无会话 |
| 本轮用户消息 | 当前分支最近一条真实用户消息及其文本；工具结果不冒充用户消息 |
| 历史 | 按声明按需提供当前请求的历史快照，保留角色、工具与附件块，不只截取预览显示的两条 |
| 配置与状态 | 有效 presetId、条目 identifier、模式、协议、用户配置、已提交变量快照 |
| 执行控制 | preview/request 用途、AbortSignal、统一截止时间 |

同次调用内数据固定。历史只读视图在本次准备中共用，避免给每个模板深拷贝一遍；未声明需要完整历史的解析器只获得所需输入。不传 API key、连接凭据、宿主 Context 或整个插件数据库。

普通动态模板输出为字符串正文，可为空；不能返回消息数组或工具定义。后续已实现 chatHistory 专用 history-patches 输出，支持按原历史深度插入和修改文本，具体边界以模板 API 为准。原条目的角色、顺序、深度、触发条件和开关继续生效，marker 只替换正文。复杂消息调整留给独立的 promptSequence。

定义文本沿用现有宏；动态正文经显式槽位插入，例如定义 content 为“当前资料：{{dynamic::body}}”。该槽位返回的字符串不再递归执行宏，不能先字符串替换再把整体送入 renderMacros。需要整段动态正文时，定义只保留该槽位。这样用户文本或检索结果中的 setvar 不会被误执行。

解析器可以进行只读的异步数据读取，不写宏变量、历史或外部状态。默认不启动额外模型任务；未来独立模型生产者通过已提交快照接入，需要等待其完成时另做显式等待配置，不在普通预览里暗中触发生成。用途字段用于控制可执行操作，不能让相同输入在预览与发送时采用两套正文算法。

## 三、统一准备流程与变量提交

~~~text
固定宿主消息、预设、变量与连接配置
  → 筛选本次真正启用且命中触发条件的模板
  → 等待动态正文解析
  → 在副本上展开模板宏、安排历史/深度、工具后前缀和提示词正则
  → 提示词序列处理（将来合入时）
  → 工具过滤、预填充判断、协议序列化、预填充兼容转换
  → 生成最终请求；预览返回它，发送交给接口并记录实际出站快照
~~~

保持 compilePreset 为同步编译核心，外层增加共享的异步准备入口。外层把本次已解析的正文映射交给编译器，不能把模板目录改成临时内容，也不修改保存的 prompts。动态正文为空时按现有空提示词规则处理，最终再判断 assistant 预填充。

当前编译位于 store.transaction 内；接入异步回调时须拆成“短事务读取/必要绑定 → 锁外解析与编译 → 短事务校验并提交”。不得持有全局写队列等待提供者，否则一个会话的慢检索会阻塞所有会话保存。

提交只校验本次依赖的有效预设、绑定、宏变量和会话版本，不因其他会话的无关工具目录刷新而失败。变量在副本上计算，成功才提交；取消、解析失败、依赖变化都不写回半成品。首版遇到依赖冲突明确中止并提示重新发送，不自动无限重跑回调或重复执行 setvar。预览始终不提交变量或会话绑定。

## 四、性能与请求生命周期

| 项目 | 首版策略 |
| --- | --- |
| 未使用动态模板 | 不初始化动态上下文、不调用提供者，沿用静态缓存 |
| 调用范围 | 只解析顺序表中启用且命中触发条件的条目；闲置、关闭或依赖缺失的条目不执行 |
| 并发 | 独立条目共享输入快照，限并发执行，建议起点为 4；按原顺序回填结果，不按完成顺序插入 |
| 调用去重 | 同一逻辑请求只准备一次；同一条目的重复解析共享该请求内的 Promise，不跨会话共享 |
| 编译缓存 | 存在动态条目时，先解析再判断缓存；键加入实际正文摘要、配置和依赖状态。旧静态缓存不能绕过回调 |
| 跨请求缓存 | 首版不在根包缓存动态回调结果。需要高成本检索缓存时由提供者按会话、分支、输入与数据修订维护 |
| 工具续轮 | 新的模型调用重新解析，可看到新增工具结果；同一请求的递归路由或传输重试复用已准备结果 |
| 解析预算 | 共用截止时间，建议默认 5 秒，排队耗时也计入；输出沿用单模板 200,000 字符及总量限制 |
| 失败 | 默认中止发送，用户可为关联条目选择跳过；缺失、超时、异常和超限均显示原因，不使用上轮正文 |
| 取消与卸载 | 合并发送取消、超时及提供者卸载信号；未完成结果丢弃，已准备并固定的请求按既有生命周期收尾 |

工具续轮重新解析不等于重复提交宏：保留逻辑请求身份和提交记录，不能仅依靠正文相同判断一次请求是否已准备。两次不同用户发送即使文字相同，也不是同一次调用。

提供者如确需跨请求缓存，只有自己能保证依赖完整时才能复用。不能只按模板版本或最后一条用户文本缓存，世界书、变量、历史编辑和分支切换都会改变结果。根包首版不建设通用依赖图或持久缓存。

异步超时只能停止等待，不能强制终止可信宿主插件里的同步死循环。重 CPU 工作由提供者使用 worker；未来脚本执行器另行隔离。日志仅记录模板身份、耗时、结果长度与失败码，不自动记录正文。

## 五、消息预览必须与发送链路同步

预览不能只展示 compilePreset.messages。工具过滤、系统消息合并、Messages 序列化、DSML 工具转换、reasoning_content 和 prefix 字段都可能改变实际请求，应纳入同一条准备与转换流程。

### 草稿预览

沿用“解析当前草稿”和“模拟下一条用户消息”，但后端调用完整的共享准备入口。解析使用当前草稿、模拟输入、当前会话/分支、有效协议与工具配置；历史和工具列表必须复用宿主发送时的准备逻辑，不能只靠 deriveMessages 近似。草稿未启用时允许手动试算，并显示“预设草稿预览”；当前会话停用注入的事实需明确，不能称其为下一次实际请求。

可纯计算的适配器序列化和预填充转换提取为共用函数，预览执行转换但不发送网络请求、不上传附件、不运行工具。带附件且需要上传才能得到最终文件 ID、或其他适配器没有可复用准备入口时，标明未确定的部分；不能伪造“与出站完全一致”。同一冻结输入、变量、解析结果和随机种子下，预览与发送准备得到的消息及请求字段应一致。

只在用户点击“解析当前草稿”时执行动态解析；输入、配置或会话变化把当前结果标记为“已过期”，不每敲一个字就调用。再次点击取消前一次预览，响应携带预览代次，迟到响应不得覆盖新结果。加载页面、切换预设和自动保存仅做廉价静态检查。

refreshPrefillWarning 改为静态结构检查，不用伪造“预填充检测”用户消息去调用动态解析。动态尾部尚未求值时标注“预填充待解析”，实际状态在完整预览或发送后更新。

### 最近实际请求：调试的权威结果

把现有“查看最近实际注入”调整为“查看最近实际请求”。记录的是最后一次转换后的出站请求，不是重新调用动态解析器，也不是重新编译缓存：

- 在最终序列化与桥接转换完成后、交给传输层时捕获实际 body；同时保留最小的消息来源映射、协议、模型、请求序号和发送状态。HTTP 失败也保留实际交给传输层的内容，发送前失败则显示准备失败，不能复用上一条冒充本次。
- DeepSeek 预填充路径复用现有 fetch bridge 的作用域与会话归属，在 rewriteDeepSeekPrefixFetch 之后观察 rewritten.init.body；当前桥接的协议观察信息不能替代正文快照。普通 Chat/官方 Messages 路径也必须覆盖各自最后的转换点，避免转换前记录一次、转换后再展示另一份。
- 关联依据为请求上下文和会话身份，不按 URL、模型名或正文猜测归属。多个会话同时发送相同文本必须隔离。第三方传输链若无法确认后续修改，应显示“适配器输入”，不能标成已验证的最终出站请求。
- 同一轮工具调用后的每次请求分别有序号，默认展示最新一条，可选择仍保留的前几次。传输重试不重新解析，若重试确实改变了最终请求体，也记录独立尝试序号。
- 在“消息预览”标题旁提供“原始消息（Raw）”按钮，查看同一快照的最终请求 JSON，保留实际 system/messages/input、工具字段、prefix 等结构。消息视图只能加来源标注和折叠，不能改写正文、合并不同消息或隐藏转换差异。

工作台打开时，在请求交给传输层后推送轻量的“新快照 ID”，页面按需读取并刷新“最近实际请求”；不等待模型回复结束，不在 token 流期间反复推送整份正文。优先复用宿主现有事件通道；若不可用，使用仅面板存活期间连接的轻量通知，不能高频轮询整个插件状态。

草稿预览与实际记录清晰标明来源和时间。用户发送时变量、宿主提示词或外部数据可能已经变化，因此发送后必须展示此次捕获结果，不能承诺早先的模拟预览永远等于未来请求。实际发送不为了匹配旧预览而使用过期正文；旧结果同时可供对照。

快照仅用于本机调试，复用现有鉴权，不进入预设导出，不保存请求头或凭据。优先复用已生成的 body 字符串，避免发送前为记录再深拷贝、再序列化全部历史。内存保留有数量和总字节上限，建议每会话最近 4 次请求、全局 32 MiB；淘汰后明确显示不可用，不能显示截断内容却声称完整。超大快照只保留摘要并提示超限，不阻塞实际发送。正文按需解析，展开面板时再渲染。

### 原始消息（Raw）入口与展示

“消息预览”标题右侧新增“原始消息（Raw）”按钮，点击后在原工作台预览区域内切换为只读原文视图，提供“返回消息预览”和“复制原文”。不跳转页面、不覆盖工作台，也不额外发送测试请求。尚无预览结果或实际请求时，按钮禁用并显示空态。

Raw 展示当前所选快照的完整请求 body，以实际交给传输层的 JSON 文本为准，不能从折叠后的消息卡片重新拼接。除了消息正文，还包含实际请求中的 system、工具定义、tool_calls、tool_call_id、reasoning_content、prefix、模型及生成参数等字段；仅保留该协议实际存在的字段，不补默认值、不重排数组、不删空值、不重新展开宏或转换 DSML。请求头、认证信息与内部来源映射不混入 body。

默认按保存的原文显示并复制，避免 JSON 解析后再序列化改变数值、转义或字段表现。内容用纯文本节点显示，不执行 HTML、Markdown 或脚本；使用预览区域内的滚动容器承载长文本。Raw 不受 chatHistory“最近两条”折叠影响，完整保留该快照中的历史。

两个视图共用同一快照 ID、请求/尝试序号和来源状态。草稿结果标记“草稿预览 · 未发送”，实际结果标记“实际请求”；仅有适配器输入时沿用其未确认提示，快照超限或已淘汰时说明不可用。新请求通知或工具续轮选择更新的是同一个当前快照，不能让消息视图与 Raw 指向不同轮次。

点击按钮仅切换视图或按快照 ID 读取已记录的原文，不触发动态回调、编译、正则或模型调用。Raw 首次打开才创建原文 DOM，收起后可释放 DOM，但不改变请求快照。复制必须返回完整原文；快照缺失时不能用摘要替代后仍提示“复制成功”。

## 六、chatHistory 默认折叠为最近两条

草稿预览和实际请求使用同一展示组件。默认显示全部预设注入条目，以及 chatHistory 中最近两条消息；两条指消息条数，不是两轮对话。历史少于两条时全部显示。

折叠摘要示例：“聊天记录 38 条，显示最近 2 条 · 展开全部”。点击后完整展开，提供“收起早期记录”。模拟用户消息若已追加到历史，就计入最近两条；工具消息也按真实历史消息计数。

折叠只作用于视图：

- 完整历史仍参与动态解析、宏、深度计算、正则、工具配对和发送。不能先截两条再编译，也不能为减少预览体积改变发送内容。
- 历史来源由编译/序列化阶段的附加映射确定，不能用“没有插件标记就是历史”推断。来源映射仅供调试，不作为未知字段发送给 API。
- 深度注入可能穿插历史；按最终消息顺序保留这些注入条目，在相应位置折叠早期历史连续段。不能把所有注入搬到 chatHistory 外面，或只展示最后两条总消息而隐藏尾部预填充。
- 工具块默认以可展开的类型和数量摘要显示；最终请求 JSON 可查看完整调用、参数、结果和推理字段，不以简单的 [tool-call] 替代全部调试信息。
- 若协议将不同来源合入同一 system/message，按可追踪文本片段折叠历史部分；混合来源暂不能安全分离时保留整个最终消息，不为凑两条而删掉注入内容。

早期历史默认不创建正文 DOM；点击展开才按原顺序构建。超长列表分批挂载并允许取消，不先创建全部元素再用 CSS 隐藏。展开/收起使用同一不可变快照，不重新解析动态模板、重跑正则或发起模型请求。折叠偏好只保存在工作台视图状态，不写入预设文件；新会话默认折叠。

首版可继续返回完整预览数据，先消除 DOM 和重复解析开销，不为折叠单独建设分页数据库。若实测网络传输成为瓶颈，再按同一快照 ID 延迟取历史正文，不能在展开时按变化后的会话重新计算。

## 七、分步实施与验收

| 任务 | 交付范围 | 必要验收 |
| --- | --- | --- |

四项以同一功能收尾，D03/D04 是交付要求，不能只上线动态注入而留下不一致的预览。T03 序列处理合入时接在既定阶段，并纳入同一最终请求观察链。

测试采用确定性模拟提供者和拦截传输，不需要真实模型。增加一组较长历史与多个动态条目的基准观察：记录准备耗时、回调次数、正文 DOM 数量及内存上限；与当前静态路径比较即可，不先建设性能测试平台。验收同时确认慢解析期间其他会话仍可保存、预览不写变量、点击完整展开不会再等待提供者。
