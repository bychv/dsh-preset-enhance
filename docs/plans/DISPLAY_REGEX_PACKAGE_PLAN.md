## 分包结论

建议同仓库维护两个可发布插件包，暂不搬迁根包，不引入第三个需要用户安装的共享包。

| 部分 | 职责 |
| --- | --- |
| 根包 dsh-preset-enhance | 预设库、工作台、SPreset 编辑器、会话绑定、请求正则、工具与协议处理 |
| packages/display，包名暂定 dsh-preset-display | 读取当前会话规则，执行显示正则，渲染 Markdown、隔离 HTML 和声明式组件，并提供原文回退 |
| shared/regex | 解析、替换、捕获及宏计算的共享源码，分别打入两个包，不单独发布 |

根包保持已有发布路径。显示包有独立 package.json、README、构建和发布命令。两个 tgz 分别检查，不能残留跨源码目录的相对引用或未解析的 workspace 依赖。预设规则功能依赖根包提供配置，不另建预设库；组件服务还可接受独立生产者提交，不要求伪造预设或聊天正文。两包通过小型版本化契约协作，无需每次同步发版。

外部插件注册提示词模板、选用后注入及跨插件组合的接口单独约定在 [外部模板注册方案](PLUGIN_TEMPLATE_CONTRACT_PLAN.md)。根包持有提示词模板目录，显示包持有渲染模板目录，通过引用组合；注册渲染模板不会自动注入提示词。

根包还规划独立的 promptSequence 接口：外部插件可在宏和提示词正则完成后、预填充最终判断及协议适配前处理请求序列副本，启停与排序由用户控制。它不依赖显示包，也不修改保存的聊天历史；未来脚本运行时可以通过适配器参与同一处理链，具体约束见上述接口方案。

## 当前实现与需要调整的地方

- src/lib/prompt-regex.mts 已有替换引擎，但 planRegexScript 只接受 promptOnly，需增加通道参数。不能把提示词判定直接用于显示侧。
- src/lib/regex-runner.mts 采用 Node worker_threads 与 Atomics.wait；浏览器必须使用异步 Web Worker。只共享纯计算和限制语义，不共享运行器。
- web/editor.js 编辑 extensions.regex_scripts；web/spreset.js 中 extensions.SPreset.RegexBinding.regexes 目前只保存和展示，不执行。两份规则不能自动合并，否则可能重复替换。
- 工作台与 SPreset 编辑器沿用现有事务、revision、自动保存和编辑锁定，显示选项也走相同保存路径。
- DSH 的 conversation.chat.node 是替换型槽，复用 assistant-step 会覆盖整个助手节点。首版不以此替换正文。
- 0.2.0-rc.2 提供会话作用域 useChat，DOM 有 data-chat-node-key 与 data-chat-group-part；正文、推理、图片和工具块分别渲染。目前没有找到公开的正文转换或围栏渲染注册入口。

这些是源码结论，尚未证明 DOM 接管可行。实施应先做小范围入口验证。

## 规则、开关和数据契约

唯一执行源继续使用 preset.extensions.regex_scripts，沿用数组顺序和稳定 ID。需要使用 SPreset.RegexBinding 的规则时，另做显式“复制到正则列表”，先检查冲突再分配新 ID，不在读取时自动迁移。

在 extensions['dsh-preset-enhance'] 中新增 displayRegex: { enabled: false, htmlEnabled: false }，与 promptRegex 并列。字段缺失按关闭处理，随预设保存和单文件分享；只安装根包也要保留字段。界面区分“已配置”和“显示包已接入”。

显示开关独立于消息注入和提示词正则开关。有效预设沿用会话绑定规则：显式绑定优先，无绑定使用默认；绑定指向已删除预设时停止处理，不自动套用其他预设。

| promptOnly | markdownOnly | 请求侧 | 显示侧 |
| --- | --- | --- | --- |
| true | false | 按请求开关执行 | 不执行 |
| false | true | 不执行 | 按显示开关执行 |
| true | true | 各自执行一次 | 独立从原始正文计算 |
| false | false | 不执行 | 保留消息写入阶段语义，不执行 |

首版显示侧只支持 AI_OUTPUT=2。用户消息、原生推理、工具参数和结果、图片与附件不处理。runOnEdit 不限制只读重绘；历史编辑后从新原文重新计算，不写回会话。

根包提供经过宿主鉴权的只读接口，按 sessionId 返回 contractVersion、规则修订、有效预设 ID、显示选项、规则和最小宏上下文。显示包不读取 state.json、不 import 根包内部模块、不拉取整个工作台状态。绑定、规则、选项或宏上下文变化时更新修订标识。

首版在会话切换、重新获得焦点及可见聊天页低频检查时刷新配置，用修订号避免重复传输，暂不搭建服务总线。接口复用宿主的认证和会话访问约束。

宏仅在任务变量副本中执行，不提交真实 local/global 状态；随机宏按消息身份和规则修订固定种子，避免重挂载时变化。未知宏保留并提示。只传所需宏变量，不下发密钥、连接配置或无关状态。显示任务不触发请求。

## 显示流程与失败回退

原始 Chat 快照与有效规则 → 提取正文和深度 → 按开关执行显示正则 → 统一分段为 Markdown、HTML、组件围栏 → 挂载自有内容 → 成功后隐藏对应原正文。

同一视图使用一个渲染调度器。正则关闭时直接解析原始正文，组件与 HTML 仍按各自开关工作；正则开启时只处理一次，再解析其结果。三个模块不能各建一套全局 DOM 观察器互相接管。

原文来自公开快照，DOM 只负责定位。禁止以 DOM.textContent 作为规则输入，禁止删除宿主 React 节点或隐藏整个助手节点。必须验证正文容器与快照片段一一对应，无法确认时保留原文，不使用模糊文本匹配。

先验证主会话、侧栏会话、同节点多个正文块、推理/正文分组以及虚拟列表。节点锚点不等于可靠正文入口；必须证明工具、推理和图片仍完整。若无法做到，先用公开 conversation.view 提供独立“渲染预览”，不扩大为整体节点替换。

流式期间维持宿主原始流式效果，稳定后才替换。中断输出只处理完整内容，不补猜未闭合 HTML。结果提供“查看原文”，停用后恢复。

同一助手轮被工具分隔的正文采用同一聊天深度，但各段独立替换，不跨工具或推理拼接；用户聊天楼层也计入深度。深度来自原始会话而非可见 DOM 数量。数据不足时跳过有深度条件的规则并提示，不猜测。

缓存至少包含会话、节点、正文片段、原文摘要、规则修订和深度。新增楼层、编辑历史、换预设或修改规则时使受影响结果失效；worker 返回时再次检查身份与修订，旧结果不能挂入新会话。

只处理可见且稳定的正文，限制并发。非法规则、超时、输出超限或定位失败时回退原文，不展示半成品。卸载和热重载释放 worker、观察器、自有容器与对象 URL，并恢复原文显示。

## HTML 分阶段做

先支持文本和 Markdown。显式 HTML 围栏或可识别的文档/片段进入隔离 iframe；普通尖括号文本不能一律当 HTML。混合内容保持顺序，无法可靠分段时展示源码。

HTML 默认关闭。开启后清洗 HTML，使用隔离 sandbox 和严格 CSP，禁止模型脚本、网络连接、表单和顶层导航。首版图片只接收受控内嵌来源，主题仅传入选定的颜色与字体变量，样式不影响父页面。采用限高和内部滚动，不为自动高度提前引入脚本运行时。

交互脚本后续单独设计：使用 allow-scripts 的不透明来源 iframe 和有限 postMessage 桥，不同时开放 allow-same-origin。依赖 parent.document、宿主 localStorage 或酒馆助手事件系统的脚本不在首版承诺内。旧预研中“交互脚本必须允许同源”的结论不采用；那是某些脚本直接访问父页面的依赖，不是执行脚本的必要条件。

未来脚本系统的接入约定见 [模板与脚本接口方案](PLUGIN_TEMPLATE_CONTRACT_PLAN.md)。逻辑脚本在独立运行时执行，经变量、视图和动作服务更新页面；HTML iframe 仍只承担隔离展示及受限交互桥，不因安装脚本系统就直接执行预设中的任意内联脚本。运行时可选，缺失时保留静态内容并停用依赖脚本的交互。

### 实现与复用选择

组件渲染放在同一个显示包中，不再拆第三个插件。优先实现一套小型声明式组件树，参考 genui 的解析、校验和生命周期。暂不直接启动 genui 的 plugin/client 入口，因为它还会注册工具、面板、动作回传和教学提示等行为。

若后续需要完整 genui 组件目录，再评估通过公开 embed 入口固定版本引入；该入口导出的是 TypeScript 源码，需要我们打包其 CSS 和资源，不能指望 DSH 动态解析本地源码。React 使用宿主实例，图表等大资源按需加载，并检查宿主模块声明。不得引用 genui 未公开内部路径。

genui 为 MIT 许可，可按许可条件复用代码。实际复制或打入其实现时，必须随发布包保留原版权和 MIT 许可，并记录来源修订；本阶段没有复制任何实现。

### 输出格式与组件范围

独立围栏名暂定 dsh-preset-ui，输入为 version: 1 的 JSON 组件树。示意：

```json
{
  "version": 1,
  "components": [
    {
      "id": "summary",
      "type": "card",
      "title": "当前状态",
      "children": [
        { "id": "energy", "type": "stat", "label": "体力", "value": 80 },
        { "id": "note", "type": "text", "text": "可以继续探索" }
      ]
    }
  ]
}
```

首批支持 text、card、row/column、table、stat、badge、progress、tabs/accordion，以及简单 input/select/checkbox/button。下一批再考虑图表；3D、复杂数学绘图、游戏和整套 genui 协议不纳入首版。

组件通过类型白名单和字段校验映射到可信 React 组件，不接受任意标签、JS、事件函数或直接展开的 DOM 属性。限制树深、节点数和字符串大小，校验链接协议。组件内不提供 raw HTML 逃生口；HTML 仍走独立隔离路径。

初版完整 JSON 校验成功后再渲染；流式期维持源码，出错保留完整源码与简短提示，不默默删掉无效组件。后续可参考 genui 的完整子组件增量解析，但不自动补造动作、提交值或组件结构。

### 与预设、正则及 genui 共存

在预设命名空间新增 componentRender: { enabled: false }，与 displayRegex 并列；单独保存与分享。聊天围栏的启用配置来自有效预设，身份和修订沿用显示接口；独立生产者视图由下文组件服务管理并由用户启用，不依赖预设绑定。插件注册目录只描述可用模板，不另建一套全局用户组件编辑库。

显示包通过根包的模板注册接口提供“组件输出模板”，用户显式加入预设顺序表后可启停和分享，需要修改正文时复制为本地模板。模板说明围栏名、字段、组件范围和示例，不在启动时偷偷注入系统提示词，运行时只按已启用预设处理。只使用独立渲染视图或由外部生产者供给数据的选项栏时，无需启用这段提示词。

模型可以直接输出组件 JSON；显示正则也可以将文本转换为组件围栏，转换结果同样必须校验。不能假设捕获值拼入 JSON 后仍合法，包含引号或换行导致解析失败时保留原文；以后需要可靠动态映射再增加明确的结构化转换能力，不默默改变现有捕获替换语义。

默认只接管 dsh-preset-ui，不接管 genui 的 dsh-ui、svg、render_ui 工具或会话面板。保留这些围栏交给对应插件；不要同时开启两套观察器接管同一节点。识别外部插件所有权失败或无法保证共存时，保留宿主原文或独立预览。

### 状态与动作

首版交互以本地折叠、切换标签、选择和填写为主，组件挂载及重绘不会自动发送消息或调用工具。按钮可把可见的结构化动作和表单数据填入所属会话的输入草稿，由用户发送。样本选项栏的追加模式直接在当前草稿末尾追加；替换已有草稿则必须明确提示，不能悄悄覆盖。

选项栏同时支持用户显式开启“点击即发送”，清楚标出会触发新回复，默认仍为追加草稿；走所属会话的标准用户消息入口，不绕过工具审批。发起动作时校验来源会话、消息身份、组件 ID 和当前修订，旧结果不可触发新会话动作，失败要显示原因。

状态键使用会话、消息/片段、围栏和组件 ID。组件局部状态与预设变量分离；正文版本变化时重置过期状态。同一消息出现在两个视图时共享逻辑状态，挂载实例分别清理。首版可用内存缓存保留切换视图时的状态，不承诺刷新后恢复表单；不保存敏感字段到全局 localStorage。

### 可定制外观的选项栏模板

显示包内置一个 choice-bar 模板，作为 choices 组件的可定制外观，外部插件也能通过独立的 renderTemplates 服务注册其他模板。注册接口同样具备版本、来源、目录读取和随插件清理的生命周期，但不与根包提示词注册表混用。注册定义描述布局、选项槽位与点击行为；publishView 引用模板创建具体实例，候选项作为实例数据单独更新，不写入模板目录。

选项栏在消息下方或会话面板显示模型生成的候选行动，用户点击后追加到宿主草稿，或在显式开启后直接发送。它不承担自由文本编辑，也不替换 DSH 主输入栏；草稿和发送复用宿主接口。已有预设的选项标签可经显式适配映射成候选项，不要求模型改用新的围栏格式。

把三部分独立配置：

| 部分 | 可以配置 | 负责方 |
| --- | --- | --- |
| 外观 | 标题、提示、字体、颜色、边框、圆角、间距、选项按钮/卡片样式、横排/列表/网格、折叠和滚动 | 模板作者与用户 |
| 选项数据与状态 | 稳定 ID、显示文字、实际填入文本、禁用状态、当前修订和执行中状态 | 生产者提供数据，显示包管理交互状态 |
| 点击行为 | 默认追加草稿；用户可开启点击即发送，或显式配置已注册插件动作 | 可信动作层 |

内置外观可直接通过属性配置，例如：

```json
{
  "template": { "providerId": "dsh-preset-display", "id": "choice-bar", "version": "1" },
  "props": {
    "title": "下一步行动",
    "hint": "点击选项加入草稿",
    "options": [
      { "id": "explore", "label": "继续探索", "value": "沿着小路继续探索。" },
      { "id": "rest", "label": "原地休息", "value": "留在原地休息片刻。" }
    ],
    "appearance": {
      "variant": "panel",
      "background": "#17202a",
      "foreground": "#f4f6f7",
      "accent": "#64b5f6",
      "radius": 12,
      "spacing": 10,
      "layout": "wrap",
      "optionStyle": "card",
      "collapsible": true
    }
  },
  "onSelect": { "action": "appendDraft", "valueFrom": "option.value" }
}
```

示例是待实现的选项栏模板契约，不是 genui 原生 schema。valueFrom 是受限字段引用，不是可执行表达式。label 与 value 不同时需能展开查看实际填入/发送的文字，直接发送模式须在操作前清楚展示该文字。appearance 使用类型与范围校验，不允许任意 DOM 属性或 JS。模板提供明暗主题、窄屏换行、可见焦点与键盘操作；选项很多时支持限高滚动或整体折叠，不挤压正文宽度。

需要更自由外观时，提供 HTML/CSS 模板模式：作者安排 title、hint、options、footer 槽位，并定义每个 option 的外观，显示包根据候选项数据重复装配可点击项。布局与 CSS 留在隔离 iframe 内，允许定制包围结构、装饰和按钮样式；缺少必需 options 槽位或出现冲突时提示并退回默认选项栏，保留候选项。首版只开放静态布局和 CSS，字段绑定及点击事件由显示包自带的受控运行时代码处理，不执行模板自带脚本。

HTML 选项栏模板属于显式启用的交互模板路径，采用隔离脚本 iframe 与前述受限桥，不能放宽默认静态 HTML 的限制。动作身份、选项数据与权限由父层保存，iframe 只提交选项 ID 和当前修订，由父层查出真实文本，不能任意替换发送内容。任意模板消息不能证明用户点击；直接发送仍需要可信父层按钮确认。普通原生模板可由可信按钮直接执行用户已开启的发送行为。

选项采用稳定 ID，不以数组下标作为动作身份。点击时核对会话、来源消息、组件修订和选项是否仍有效，再读取所属会话最新草稿追加文本，保留现有内容与附件。选项文字变化后旧按钮事件不能发送旧内容；调用失败显示原因，不自动改走另一条路径。执行中防止重复点击，直接发送成功后标记该次操作完成，用户要重复发送须明确再次操作。

独立模型或变量插件可以在正文结束后发布或单独重生成整组选项：等待时保留旧选项并标明更新中，成功后原子替换；点击与提交中的操作固定其已确认的修订，不能被新选项悄悄改写。仅重排或换皮肤时按 ID 保留折叠等状态；选项删除后清除相关选中状态。没有稳定 ID 的旧格式由适配层按内容生成，内容改变视作新选项，无法区分的重复项不宣称保持身份。所有更新都不改写已经填入宿主的草稿，也不自动触发点击或发送。

模板结构、默认外观、选项字段映射和动作引用可以随预设导出；本轮生成的候选项、用户发送授权和执行状态不随模板分享。主题或模型数据不能替用户开启直接发送。“重新生成选项”可作为独立插件动作接入，只更新对应选项栏，不重生成正文，也不伪装成一条聊天消息。

为脚本扩展保留可选的 scriptBinding 与命名空间 actionId 引用，关联到组合清单声明的脚本实例；模板仍只描述外观和数据绑定。未来脚本可筛选候选项、联动变量或处理点击后的业务逻辑，结果通过相同的带修订视图接口提交。脚本不直接修改选项 DOM；点击只投递一次业务动作，主栏/侧栏的重复挂载不重复执行。脚本离线时保留候选项，并按动作依赖显示不可用原因，内置追加草稿不受影响。

## 独立模型更新变量的渲染接口

组件服务由显示包提供，供其他插件或独立模型的控制程序调用。模型返回结构化结果，由受信控制程序校验后提交；渲染器不负责启动模型，也不把访问凭据放进围栏或 iframe。该服务不依赖是否开启预设注入，不需要写一条假的助手消息来刷新界面。

公开能力保持精简，接口命名暂定 RenderServiceV1；以下是本插件的接口提议，不是 MVU 已有 API：

| 操作 | 用途 |
| --- | --- |
| publishView | 创建视图或发布新的模板版本，提供变量 schema、初始值和可用动作 |
| updateVariables | 在既有模板上原子更新变量，返回新的状态修订号 |
| beginUpdate / finishUpdate | 标记独立更新任务及其目标，提交结果或记录失败、取消；更新中继续显示上次结果 |
| readView / subscribe | 获取快照及订阅已提交状态，断线重连先读取完整快照 |
| removeView | 移除调用方拥有的视图并清理挂载状态 |

服务端注册受限 Cordis 服务，客户端通过宿主认证的远程接口读取和订阅；需要跨进程的控制程序可经同一校验层的认证 HTTP 接口提交。不要另开匿名端口，也不要让任意模型文本声明自己的访问身份。调用方身份、允许的会话和 namespace 在注册或授权时确定，不能信任请求体中的 producerId。

模板和变量分开：模板由 publishView 更新并版本化，普通变量更新不能改组件类型、动作定义或权限。组件属性绑定变量路径，不用 JS 表达式或 eval；文本作为文本处理，不能通过变量值注入新的 HTML 或动作。

示意更新请求（具体路由留到实现阶段）：

```json
{
  "contractVersion": 1,
  "sessionId": "session-example",
  "namespace": "state-agent",
  "viewId": "status",
  "templateRevision": 2,
  "expectedRevision": 12,
  "requestId": "update-013",
  "sourceEpoch": "epoch-example",
  "sourceTurn": "turn-example",
  "sourceRevision": 24,
  "set": { "energy": 80, "options": ["继续探索", "原地休息"] },
  "unset": []
}
```

首版用明确的 set/unset 键更新，数组整项替换，不提供复杂的任意路径补丁语言。按注册的 schema 检查键名、类型、大小和范围，拒绝危险属性键。整笔校验成功才提交，失败时界面保持上次成功状态并显示原因。

expectedRevision 防止同一目标的并发覆盖，重复 requestId 幂等处理。sourceEpoch/sourceRevision 表示目标分支和正文版本，另由 beginUpdate 返回更新任务 ID；提交时核对目标是否仍有效，以及是否已被同一目标的新任务取代。不能因为正文已结束、出现下一条消息或界面切换会话，就拒绝有效的迟到结果；也不能简单比较 turnId 字符串大小。主界面和侧栏订阅同一状态，但不能跨会话共享变量。

显示运行状态与预设宏变量分离，变量更新不会自动调用 setvar，也不会暗中改变下一次模型请求。需要模型读取这些状态时，由调用方明确读取或通过另行配置的提示词绑定实现。

默认有两种视图：live 会话面板订阅当前分支的有效最新状态；snapshot 消息卡片绑定某次正文版本及其选中的组件修订。snapshot 允许对应结果晚到，也允许用户只重生成该卡片的数值，并保留旧修订；它不在正文结束时立即冻结。一次 live 更新不能改写所有历史卡片，只有显式声明 live 绑定的卡片才随最新状态刷新。

与临时的表单输入不同，已提交视图需要持久化，重启后恢复。显示包保存模板引用、选中的组件修订和恢复显示所需的只读快照；接入外部变量插件时，变量真值与更新规则仍由该插件负责，不建立第二套可独立写入的变量库。预设导出只带模板、字段 schema、适配映射和默认值，不携带运行时变量、用户回答、请求 ID 或访问凭据。生产者停用后保留最后快照并标明不再更新，不让旧生产者继续写入。

### 正文与组件独立完成

正文继续流式输出并正常结束，不挂起正文的结束信号等待变量模型。组件挂载目标使用会话、分支、消息正文版本和稳定的组件槽位 ID，不依赖围栏出现顺序或临时 DOM。正文没有输出组件围栏时，也允许已配置的消息附属槽位接收稍后发布的组件；定位能力不足时放入会话面板，不能伪造一条助手消息占位。

| 场景 | 界面与提交行为 |
| --- | --- |
| 正文完成，变量尚未返回 | 显示等待状态，正文可正常阅读；模板本身也可稍后发布 |
| 已有结果，单独重生成数值 | 保留旧结果并标记更新中，只替换该组件的数据修订 |
| 更新失败或取消 | 保留旧结果并显示原因，允许再次重试 |
| 用户已进入下一轮 | 结果仍可写入其所属消息；是否推进会话最新状态由变量提供者判断 |
| 目标正文被重生成、删除，或同一目标已有新任务 | 旧任务不能覆盖新的组件结果 |
| 切换会话、视图或暂时卸载组件 | 服务端任务继续，结果只写原目标，重新挂载读取已提交快照 |

数值重生成必须复用该目标原先的输入依据，例如该轮正文及该轮之前的变量快照，而不是在上次生成结果上重复应用增量。具体合并、回滚和重算由变量提供者负责；渲染器接收校验后的完整投影，不自行执行模型输出的变量修改脚本。新的有效结果替换该目标选中的修订，旧结果保留供回看。

历史某轮的变量重生成可能影响后续楼层。默认只更新选定卡片，并将依赖旧变量的后续状态标为待重算；没有提供者明确提交新的有效状态链时，不能把历史迟到结果直接当成 live 最新值。首版不自动重算整段历史。正文继续生成时若所需变量尚未就绪，提示词绑定使用最后已提交值并标明待更新；需要严格等待的工作流由变量提供者另行配置。

重启后恢复最后已提交结果，并把无法确认是否仍在运行的任务标为中断；不自动重复启动付费模型请求。模板版本未变化的数值更新尽量原位刷新，保留与更新无关的折叠、标签页和未提交表单状态；字段已删除或含义已变化时才明确重置相关输入。

### MVU 类变量提供者接入

预留一个薄适配层即可：读取指定消息/分支的快照、订阅已提交状态，以及可选的请求数值重生成。注册时声明是否支持历史定位、schema、重生成和后续状态重算；不具备某项能力就不显示对应操作，不要求首版移植完整 MVU 运行环境。

MVU 的公开定义包含结构化 stat_data、schema 和变量更新事件，但更新结束回调仍可修改数据，消息更新前回调也不等于保存成功。因此适配层应在变量提供者成功提交后回读并发布带修订的快照，不能直接把某个“更新结束”事件视为持久化完成。接口依据见 [MVU 变量与事件定义](https://github.com/MagicalAstrogy/MagVarUpdate/blob/beta/src/variable_def.ts)，接入时还需固定所支持的版本。

变量提供者拥有结构化状态、更新指令解释及历史依赖；显示包只负责字段绑定、展示和动作转交。当前预设宏的字符串变量不承担这一职责，也不自动与 MVU 双向同步。不同提供者使用独立 namespace；组件数据绑定到提供者及明确的变量路径，避免同名字段相互覆盖。没有可靠提交订阅时，可用显式刷新回读快照，不能猜测更新已成功。

## 正则转换成组件围栏的可行范围

不能承诺用通用代码把任意正则替换模板转换为原生组件。正则通常只描述文本替换，不包含布局意图、变量含义或脚本动作契约。已知结构可以确定性转换；未知模板应保留隔离 HTML 路径，原生组件只是可选渲染方式。还需区分已有规则输出、本包组件协议与 genui 真正支持的格式，不能只改围栏名。

| 来源 | 处理方式 |
| --- | --- |
| 替换结果已经是合法组件 JSON | 校验后直接进入组件渲染 |
| 捕获到日期、位置、状态或选项 | 显式字段映射，构造对象，再 JSON.stringify；也可直接提交组件树而不生成文本围栏 |
| 已知 HTML 卡片模板 | 可保留 HTML 外观并适配字段与动作；用户选择原生组件时，才使用已注册适配器转换 |
| 任意 HTML 与任意脚本 | 保留隔离的静态 HTML 展示；脚本交互须另行适配，不承诺自动还原 |

genui 的真实协议根字段为 items，文本组件使用 content；本方案的 version/components/text 示例不是同一种协议。若新增 genui 兼容输出，提供明确的编码适配器，经过其 schema 校验后调用公开 embed 渲染入口或导出 dsh-ui 围栏。仍由本显示包管理自己的结果容器，不把已转换内容塞回宿主 DOM 等待另一插件猜位置，也不宣称支持 genui 所有组件、panel 或动作语义。

直接把 $1 拼进 JSON 字符串遇到引号、换行、反斜杠就可能失效。推荐增加显式的“捕获值到组件字段”配置，保存在本插件命名空间、以规则 ID 关联，保留原酒馆规则不变；禁止悄悄改变既有 $1 替换语义。不要默认给每条消息额外调用模型做转换；模型可辅助生成一次性的映射草稿，由用户预览后保存。

普通显示正则仍按原顺序执行，先得出最终显示副本，再识别已知模板和组件。针对原始标签的专用捕获映射，要显式替代选定美化规则的渲染职责，显示清楚哪些规则被替代；不能既输出原 HTML 又重复插入组件。如果后续正则还依赖该规则的文本输出，首版保留整条文本链，再从最终 HTML 提取，不能提前吞掉中间内容。

映射只是显示投影，不改写原始历史或提示词侧规则。工具、推理块和附件不参与转换。适配器依据规则 ID 关联及模板结构/版本特征识别，不按预设名称猜测，不因为文本含有 option 就随意接管。

### 保留自定义模板，不强制转成统一卡片

把数据契约与展示模板分开，同一份变量可以绑定两种渲染方式：原生声明式组件，或隔离的 HTML/CSS 模板。模板保存 ID、版本、所用渲染方式、字段绑定和允许的动作；独立模型通常只更新变量，不必重新生成整份界面。外部生产者确实需要更新模板时，另行发布模板版本，不能把模板变更混在普通数值更新里。

HTML 路径尽量保留原布局、主题和响应式样式，但静态展示不代表原脚本自动可用。对已适配模板，用受限的数据更新桥刷新字段，通过动作桥请求追加草稿等操作；变量不能作为新的 HTML 或脚本执行。纯静态模板可以重新生成隔离文档，需保存并恢复明确支持的局部状态。依赖酒馆父页面、外部助手脚本或特殊变量函数的模板，需要逐项提供适配能力；缺失时明确显示哪些交互不可用。

围栏是模型直接输出组件的一种输入形式，不是组件存在或更新的必要条件。MVU 类插件提交快照后，显示包直接刷新相应视图，不把变量重新编码成围栏写入正文，也不用再调用模型把 HTML 转成 JSON。

### 模型辅助转换的定位

代码适合解析已知标签、字段映射、协议编码和已登记的动作替换；它无法可靠推断任意脚本的意图，也不能从任意 CSS 自动还原为有限的组件目录。模型可以帮助理解陌生模板，生成字段绑定、样式迁移和动作改写的草稿，但也不能保证无损转换。

因此将模型转换设计为用户主动运行的“一次性模板迁移”，在导入或模板变更时使用，正常聊天和变量刷新不依赖它。用户选择保留 HTML 外观或转为原生组件，提供必要模板片段和示例数据，预览与原模板对比后保存适配结果；不默认发送整份预设或聊天历史。迁移产物与模板版本绑定，模板改变后提示重新核对，而不是继续套用旧映射。

模型生成结果仍按普通外部内容处理：校验组件 schema、字段与动作范围，HTML 使用相同的隔离策略；不能因为模型生成了脚本就授予父页面或存储访问权限。首版先做好手工映射与模板预览，模型迁移入口可后续增加，不影响组件异步更新或 MVU 适配层落地。

## 本地复杂样本：选项栏与脚本兼容

已只读检查用户指定的本地样本，未执行其中脚本。样本有 27 条正则，4 个替换模板带内联脚本，另有 6 个酒馆助手脚本。以下只记录功能结构，不复制样本内容或具体名称。

| 功能 | 已观察到的依赖 | 兼容策略 |
| --- | --- | --- |
| 选项栏 | 解析旧式 option 元素或竖线分隔文本；默认追加草稿，可选直接发送；父页面主题和按聊天保存的设置 | 可转换为 choices 组件，重新实现两种点击行为和会话内偏好同步；保留 HTML 外观时另做动作桥适配 |
| 问答卡 | 提取问题、候选答案或用户填写内容，组合带问题属性的回答标签并追加输入框 | 可转换为 questionnaire 组件，保留回答格式与属性转义；自定义布局走 HTML 模板适配，复用草稿动作 |
| 状态栏与并行事件卡 | 捕获结构化字段，解析条目，读取主题变量 | 保留 HTML 并绑定变量，或转换为 keyvalue/stat/event-list，主题由显示包提供 |
| 修复/撤销卡 | 父页面自定义事件，外部助手脚本读取并修改聊天消息及修复记录 | 可展示状态，但修复动作标为未适配；后续须单独实现受控历史修改服务，不能假装点击成功 |

新增 choices/questionnaire 是常用组件的组合，不需要移植原样本约数万字符的 HTML/CSS/JS。保留基本布局与主题能力，不承诺像素级还原。

内置聊天动作统一为 appendDraft、replaceDraft、sendMessage 三类；变量重生成等插件动作使用独立注册的命名空间，不混入聊天发送协议。appendDraft 在点击时读取所属会话的最新草稿，再按换行策略追加，保留附件和结构化引用；不要修改 textarea DOM。如果宿主无法可靠保留现有输入结构，则提供复制/合并预览，不退回 DOM 事件模拟。replaceDraft 单独确认已有内容的替换。sendMessage 只在用户主动点击且已开启直接发送时调用标准会话发送入口，不以修改历史加触发命令来冒充发送。

样本原有的主题和点击模式跨楼层同步，迁移为显示包按会话保存的偏好；不读取酒馆的 localStorage，也不让独立模型通过变量更新替用户开启自动发送。点击时显示 pending，防止重复触发；发送失败显示错误，不自动改走另一条路径重复发送。

保留原 HTML 外观时，可为已知模板做定向改写，将父窗口调用替换为有限 postMessage 桥；这也是模板适配，不是通用酒馆运行时。桥接逐条校验 source iframe、挂载身份、会话、nonce 和请求 ID，仅允许已授权的动作；重绘后旧 frame 的请求无效。脚本 iframe 不具备父页面 DOM、cookie 或存储访问能力。

不能把任意 iframe 发来的消息当作用户点击：不透明来源脚本无法通过 postMessage 证明可信点击。发送动作应由可信的原生组件按钮承担，或在父页面展示真实确认按钮；不能让未知脚本自行请求发送。已知选项栏首选原生组件方案，最容易准确保留行为。
