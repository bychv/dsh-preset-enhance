# Agent Notes

这里为后续接手代码的 agent 保存决策依据：为什么选择当前做法、哪些替代方案被放弃，以及修改时必须守住的边界。功能怎么用仍写在 `docs/`，不要在这里复制接口手册或逐条记录开发过程。

组织方式参考 [DSH Agent Notes](https://github.com/deepseek-ai/deepseek-harness/blob/master/.agents/notes/README.zh.md)。本仓库采用中文单文件，不要求双语副本、同步哈希或额外门禁。

## 文件位置

使用 `状态/类别/YYYY-MM-DD-主题.md`，主题用简短英文连字符名称。日期取本仓库首次记录该决策的日期；补录旧决策时另在正文写明可核实的历史来源，不猜测日期。

| 状态目录 | 阅读方式 |
| --- | --- |
| `proposed/` | 有待实施或尚未完成的方案，不能视作现有功能 |
| `implemented/` | 已落实的决策，相关路径、字段和行为应与代码同步 |
| `rejected/` | 未采用但仍值得保留理由的方案 |
| `archived/` | 已失去当前指导作用的历史记录，不作为实现依据 |

类别按主题选一个：`feature`（能力）、`bug-fix`（缺陷原因）、`simplification`（删减）、`architecture`（运行时结构）、`process`（协作流程）、`testing`（验证策略）。有文件时再创建目录，不铺空目录。

目录本身用于发现笔记，不另建逐文件索引。查找时先列出文件，再搜索关键词：

```powershell
rg --files .agents/notes
rg -n '模板|协议|会话' .agents/notes
```

## 什么时候写

先检查已有记录。只有代码、测试和现有文档不足以解释一个有长期价值的选择时才写，例如跨插件归属、请求改写顺序、持久化兼容或安全边界。小范围样式、变量改名和常规修复通常不需要。

同一决策继续更新原记录；方向改变时另写新记录并相互链接。替代方案只记录实际考虑过的选项，不为凑格式编造历史。已有 `docs/plans/` 继续作为原设计依据，不批量搬迁或假定其已实现；需要深化某个决策时再链接或拆出笔记。

## 笔记格式

首行写主题，随后写状态。正文中文即可。可复制 [笔记模板](TEMPLATE.md)，删除不适用的状态段落。

- 提案说明问题、准备采用的方案、其他选择、验收标准与风险。
- 已实施记录说明问题、最终决定、其他选择、影响及验证证据；未完成内容明确另列，不写成已交付能力。
- 否决记录保留原提案，在状态下说明未采用的原因。

每份记录都要给出相关源码、接口或测试的相对链接，避免复制大段实现。验证写清执行了什么、没执行什么；不能把预期测试结果写成通过。

## 维护

代码变化影响记录中的路径、字段、默认值或边界时，在同一次修改中更新事实。完成提案后将文件移到 `implemented/`，更新状态并把方案改写为实际结果。放弃时移到 `rejected/` 并说明原因。移动后检查入站与出站链接。

只有已实施且不再指导当前工作的笔记才归档；仍在约束协议、持久化或权限的决策应留在活跃目录。归档时注明日期和替代文档，后续不将历史描述当作当前契约。

笔记状态用于表达事实，不要求每个任务先获批准，也不替代用户的指令或发布授权。
