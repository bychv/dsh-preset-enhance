# 用决策笔记支持 agent 接续开发

Status: implemented

## 问题

本仓库既有已交付接口，也有分包、渲染和脚本等后续方案。agent 只阅读计划或先前对话，容易把规划当成事实，或在接续任务时重新讨论已经确定的边界。

## 决定

根目录的 [AGENTS.md](../../../../AGENTS.md) 提供代码和文档入口。决策理由放在 [.agents/notes](../../README.md)，按状态和类别查找；用户手册、接口契约、实施计划与验证记录继续留在 [项目文档](../../../../README.md)。

采用中文单文件及简单状态标记。只为具有持续指导价值的选择新增笔记，保持已实施记录中的事实与代码一致。

## 考虑过的替代方案

**完整照搬 DSH 流程。** 上游包含双语配对、同步记录与多种文档门禁。本仓库当前以中文协作为主，不引入这部分维护工作。

**把全部旧方案搬到 notes。** 旧方案混合设计依据、实施状态与交接信息，整体搬迁容易造成状态误判。因此保留原位置，在具体决策需要独立记录时再提取并链接。

## 影响与验证

接手 agent 可以区分提案和已交付决策，同时通过原有 API 文档核对接口。维护者需在改变相关事实时同步记录；常规局部改动无需新增笔记。

本次只加入文档约定和导航，不改运行时行为。验证范围为 Markdown 相对链接与 Git 空白检查，不涉及模型调用或宿主测试。
