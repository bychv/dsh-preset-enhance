# DSH 系统模板分段编辑与本轮组装结果复用

Status: proposed

## 问题与核对范围

2026-10-28 在 next-ver 检查插件系统模板、请求注入和编辑器代码，并只读核对沙盒 DSH `0.2.2-alpha.2` 源码，提交 `f3803c96974ad4a94195fb97e5c637e9c2a3afe3`。本记录提出后续优化，不代表已经修改运行逻辑。没有执行模型请求、浏览器测试或新增运行测试。

当前按预设、模式分别保存模板、恢复默认、变量宏和历史系统提示移除继续有效，见[现有接口](../../../../docs/api/DSH_SYSTEM_TEMPLATE.md)。本提案不重新设计这些能力。

### 宿主实际组装顺序

1. Agent 在每个 step 开始确定模型，并通过 `tools.resolve` 得到本轮准入的 `toolSet`。
2. `systemPrompt.assemble` 合并全局与作用域注册，较近作用域的同名段落、变量覆盖较远作用域；段落按顺序排列，动态函数在此求值。
3. 组装经过 `system-prompt/assemble` waterfall；若存在 `complete` 段落，宿主在 waterfall 后恢复它作为唯一系统正文。工具声明仍由 provider 管理。
4. `renderPrompt` 插入变量并拼接系统正文。发送前 `refreshContext` 只刷新运行环境上下文，不重新执行系统段落、变量和工具 provider。
5. 系统正文、运行环境快照和工具 schemas 分别进入请求。运行环境快照通常是独立的 user 消息，不属于系统正文编辑内容。

因此应沿用宿主已提供的结构，不能从最终字符串按空行、标题或关键词重新切段。

### 当前实现的限制

- [模板读取](../../../../src/lib/dsh-system-template.mts)读取 `assembly.sections` 和变量，将段落合成一份可编辑模板；`dynamicSection()` 依靠名称名单决定哪些段落保留整段宏。未知第三方动态段落会默认展开成当时的文本。
- [编译](../../../../src/lib/preset.mts)对未修改的模式使用 `{{dsh::prompt}}`，仍跟随当前完整默认内容。保存自定义模板后则保存整篇字符串：只改一个位置，也会固定其他已展开段落，并且不会自动纳入此后新增的段落。
- [请求入口](../../../../src/index.mts)在 `llm/stream` 阶段再次调用模板读取；宿主此前已完成本轮组装。插件再次组装没有传本轮 `toolSet`，会重新执行 provider 和 waterfall。
- 官方工具 executor 的段落可通过 `definitions(scope, toolSet)` 生成 SDK。没有 `toolSet` 时读取的是当前可见注册集合，而不是本轮准入集合。因此存在提示词工具说明与实际 schemas 不一致的风险；这属于源码确认的路径差异，尚未针对该情形做真实宿主复现。
- 自定义正文中引用的段落宏，在提供它的插件停用后可能无法解析。当前明确报错可以防止静默丢内容，但不适合未来“未修改、跟随默认”的段落继承语义。
- 宿主公开的 `AssembledSection` 只有名称、已求值正文和插值标记，没有原始 provider 是字符串还是函数的信息。不能仅凭组装结果可靠识别所有动态段落。

## 建议方案

### 先保证请求使用同一份组装依据

优先复用宿主本轮实际接受的组装结果，使系统正文、变量和工具说明基于同一次准入。不要为减少一次调用而引入跨轮复用动态内容的长期缓存，也不要再调用一次 `tools.resolve` 假装得到同一轮的准入集合。

实施前确认可用的公开生命周期及请求关联方式；优先利用已有组装接入路径，避免新增分散的方法包装。`system-prompt/assemble` 事件内看到的对象不一定就是最终返回结果，因为其他监听器和 `complete` 规则仍可能修改它。不能直接缓存事件入口对象并称为实际发送依据。

结果必须按 Agent、step/请求身份关联，而非只按 sessionId 缓存；区分工具续轮、重试、取消、模式和模型切换，以及多个会话。插件内部转发的同一请求应复用原关联。作用域租约及 `toolSet` 的所有权仍归宿主，不延长其寿命或自行释放。缺少可验证关联时保留明确的独立预览路径，不误取上一轮快照。

草稿预览可以独立组装，但它只是当前草稿的估算；最近实际请求及 Raw 继续以实际请求快照为准。发送与预览共享相同的“结构转换、覆盖、宏解析”逻辑，不要求发送复用之前的草稿结果。

### 按段落继承，保存局部覆盖

保留置顶「DSH 系统提示词 · 模式名」和现有总开关。内部利用宿主段落名称作为身份，提供三种状态：

- **跟随默认**：每次使用宿主当前段落，不持久化其正文快照。
- **自定义**：保存该段落的用户模板，变量宏继续在运行时解析。
- **禁用**：明确排除该段落，不等同于删除自定义内容后恢复默认。

未改动段落默认全部跟随宿主，不再依靠段落名称名单猜测动态性。新增段落按宿主顺序自动出现；默认继承的段落随来源停用而消失，重新启用时恢复。首版保持宿主顺序，不增加拖拽排序或复杂合并规则。

自定义或禁用设置仍按“当前预设 + 模式 ID + 段落名称”隔离。来源暂时消失时保留覆盖配置，面板标出不可用，不把它当作新的孤立段落强行注入；来源恢复后重新应用。用户在自定义正文中主动引用却缺失的变量或段落宏，仍明确报错，不静默删掉。

提供单段恢复默认和当前模式全部恢复默认；恢复其他模式、修改其他预设的行为保持不变。展开动态段落后只有真正的变量宏继续更新，已经写入自定义正文的其他文本属于用户固定内容，不承诺自动恢复其原始函数逻辑。

### 旧模板与 UI

旧 `dsh_system_prompt_templates` 整篇字符串继续按原语义读取，包括空字符串、原有宏及 URI 编码宏兼容。不得通过猜测边界自动拆分已有模板。新增分段覆盖字段的名称和版本规则在实施时明确，并同步保存、导入、导出和分享格式；旧模板与分段模式必须有明确优先级，不能叠加两次。转换到分段编辑应是用户明确操作，不能因升级静默丢掉旧正文。

面板在现有 DSH 条目内部展示可折叠段落，显示简短名称、状态及编辑区，不额外增加多个顶层配置卡。提供完整组装预览；运行环境上下文另行只读展示，并清楚区分其不属于系统正文。不要在界面铺设本提案的实现解释。

本提案不改变专用预设模式的注入语义，不更改工具启停及权限，不扩大运行环境上下文的移除范围，也不把 `required` 上下文作为普通可编辑段落。系统提示开关现有行为保持独立。

## 实施顺序与性能

1. 先验证并解决本轮组装结果复用，重点覆盖动态 SDK 与真实工具准入的一致性。
2. 再引入分段覆盖数据和编译逻辑，保留旧整篇模板路径。
3. 最后调整编辑 UI、单段恢复默认、预览及分享往返。

只缓存可复用的模板结构和编译结果，不缓存跨轮动态值。工作台可合并重复刷新，在可见且相关状态变化时更新；宿主 `system-prompt/change` 可用于注册变化通知，但它不能替代每轮动态函数求值。不要通过频繁完整组装轮询页面，也不要把过期请求的结果写回切换后的模式草稿。

## 考虑过的替代方案

- 继续扩充 `dynamicSection()` 名称名单：可以补单个官方段落，但无法覆盖第三方插件和以后新增的动态内容，不作为长期方案。
- 所有段落都拼成宏后让用户编辑整篇：比冻结文本更安全，但仍固定保存时的段落集合；新增段落无法自动进入，缺失段落仍易导致解析错误。
- 自动拆解旧自定义正文：用户可能已重排、删改或混合多个段落，无法可靠还原，保留旧模式更稳妥。
- 仅缓存最近一次 session 组装：不能区分预览、工具续轮、重试或异步请求，容易串用，不采用。

## 验收与风险

- 未编辑时系统正文与宿主本轮接受的结果一致，动态工具 SDK 不包含未准入工具；工具 schemas 与执行准入没有因模板编辑被改变。
- 修改一个段落后，其他段落仍随宿主更新；暂时为空的段落后续能出现，第三方段落启停与热重载正确。
- 按预设和模式隔离，覆盖新会话首条消息、输入后切模式、模型切换、同会话切预设，以及两个会话并行。
- 验证工具续轮、取消、失败重试和旧请求晚返回，不复用错误的组装结果；覆盖 `complete` 段落及其他 waterfall 监听器。
- 旧整篇模板、空模板、自定义宏、单段/整模式恢复默认，以及导入导出、自动保存均保持预期行为。
- 草稿预览和请求使用同一转换逻辑；实际请求与 Raw 展示对应本次发送，不拿新的草稿结果冒充已经发送的内容。
- 以现有[系统模板测试](../../../../tests/dsh-system-template.test.mjs)为基础增加必要边界测试，再使用沙盒假端点验证实际请求。无须默认运行大量真实模型调用。

本次只完成源码调查和提案记录；上述验收项均为待实施验证。
