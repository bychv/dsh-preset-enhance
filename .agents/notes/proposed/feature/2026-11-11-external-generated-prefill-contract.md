# 外部生成式预填充的模板与读取接口增强

状态：提案。仅记录接口增强方向，未实现；不在预设插件内新增模型调用功能。

## 目标与归属

外部插件可以在发送前，根据生成指令和最近 N 轮正文调用独立模型，将结果交给已有 `dshDynamicPrefill` 条目作为本轮前缀。主包只提供受控读取、动态模板解析、生命周期与最终注入，不新增第三种内置生成模式，不接管外部模型配置或 SDK。

外部插件负责 baseURL、model、API key 环境变量名、生成指令、上下文轮数、超时、max_tokens、temperature、输入/响应长度限制和失败策略。密钥不写进预设、分享包、Raw、模板目录或日志。可优先使用 DSH 公开操作接口；若调用宿主 LLM，使用明确的辅助请求用途并防止再次触发预设生成。

截图提到的 dsh-continuation-prefill 仅作为需求来源，本次未审阅其源码，不声称其实现已验证。不把截图中的策略直接升级为所有动态模板的默认行为。

## 已有能力与缺口

依据[模板 API](../../../../docs/api/TEMPLATE_API.md)、[公开类型](../../../../src/template-api.d.mts)及[动态解析实现](../../../../src/lib/dynamic-templates.mts)：

- 可注册异步 resolver，声明 latest-user/history 输入，读取只读历史、变量、配置和 AbortSignal；结果按字面文本插入。
- 上下文有 requestId、historyRevision、purpose，但没有承诺稳定的 turnId、步骤阶段或跨重新准备的重试标识。不能仅凭 requestId 宣称同轮只生成一次。
- 当前最多并发 4 个解析器，共用 5 秒截止时间；工具续轮重新解析，主包不跨请求缓存结果。该约定不足以直接支撑较慢的小模型调用。
- 已有 `dshDynamicPrefill` 末尾注入逻辑，见[既有决策](../../implemented/bug-fix/2026-10-19-prefill-detection-and-force-switch.md)和[编译器](../../../../src/lib/preset.mts)。应增强其外部关联契约，不再建第二个动态前缀标记。
- [预设只读 API](../../../../docs/api/PRESET_READ_API.md)可读取保存内容及当前绑定，不提供解析执行或聊天历史；应继续保持这一安全边界。

## 建议的最小接口增量

以下字段与能力名仅为草案，实现时统一公开类型与文档，通过 capability 探测兼容旧提供者。

1. **请求生命周期上下文**：给动态 resolver 提供宿主可确认的会话轮次 ID、步骤/尝试标识、首模型请求/工具续轮阶段、预览用途，以及本次快照版本。无法可靠获取时明确标记未知，不根据最后消息角色猜测轮次。外部提供者可声明只参与首请求；工具续轮默认不触发这一类生成器。
2. **受控正文读取**：提供明确的纯文本上下文投影或同等 helper，包含本次待发送用户消息、最近 N 个用户发起轮次及顺序信息。排除 system、结构化 reasoning、工具调用/结果、图片及附件字节；工具调用中夹带的普通文本也不作为默认正文。内联 think/thinking/reasoning 区段需处理未闭合标签并保守排除，避免把残缺思考段发给辅助模型。裁剪按轮次和显式字符预算进行，超限返回可识别错误；不静默截断。该投影用于外部生成器，不改变既有 history 深度坐标语义。
3. **动态前缀关联**：允许外部模板明确关联 `dshDynamicPrefill`，沿用默认自动关联、冲突时选择、启停与热重载机制。只允许一个有效生成来源；保留用户条目开关和位置配置，最终前缀仍由主包统一追加。返回值作为字面文本，不递归执行宏或再次调用 resolver。
4. **超时和取消**：为显式声明的耗时提供者增加有上限的超时配置，保持普通解析器默认预算。发送取消、切换有效绑定、提供者停用/卸载和超时均须传递 abort，迟到结果不得注入。避免简单移除全局截止时间。
5. **同轮复用**：提供稳定生命周期键与失效通知，外部插件缓存生成结果并合并并发中的同一任务。键至少覆盖会话、轮次、输入快照、预设/绑定、提供者版本及配置；新轮、编辑历史、切换预设、配置变更不能复用旧值。缓存不持久化、不导出；明确有界容量与释放时机。传输重试复用已准备请求，重新准备时也能识别同一生成任务。取消一个预览不能误杀实际发送共用的任务。
6. **失败和回退**：现有 abort/skip 不等于“回退静态前缀”。若需要后者，提供显式且可观测的结果状态，例如 generated/fallback/skipped，主包只消费结果和已声明的回退来源。外部插件决定何种错误可回退；主包必须告知预览实际采用了哪一种，空返回值不能被误报为生成成功。
7. **读取能力补齐**：内部受信任插件可以读取指定会话当前有效预设、条目标识/启用状态、动态前缀关联及思考/正文目标、显示前缀设置等只读摘要，返回 revision。优先通过 resolver 快照提供本次请求信息，避免外部插件绕工作台管理 API 二次读出不同版本。持久化读取与请求快照读取分开，不把请求期历史或解析执行加入现有 HTTP/preset_read 默认权限。

## 前缀冲突与后续请求

外部生成器可以要求“追加前末条必须是 user”，但这应是可声明的提供者约束；普通预设可能在用户消息后合法注入 system，不能把该限制硬编码到所有预填充流程。生成前提供候选尾部摘要并尽早检查，生成后在最终注入边界复核，检测其他插件已追加的 assistant 前缀，按明确策略拒绝或由用户选定单一来源，绝不静默叠加或覆盖。

工具续轮不再调用外部生成器；是否复用既有前缀或采用现有 postToolPrefix 配置由主包原有逻辑负责，不能误将“跳过生成”解释成清除工具续轮设置。Messages 等不支持预填充的协议应在生成前阻止无效付费调用，并在预览解释原因。思考/正文目标和“显示前缀”继续使用主包现有设置，外部插件只提交文本及来源，不自行改历史或拼 API 请求。

## 预览与权限

页面加载、自动保存、启停检测不执行模型生成。显式“解析当前草稿”允许执行时，要能告知用户将调用外部生成器；普通查看优先展示已有结果或待解析状态。预览与实际请求使用同一准备流程；预览结果只有快照和配置完全匹配才可复用，实际发送快照始终以真实请求为准。Raw 显示最终发送前缀及必要来源/回退状态，不显示凭据、辅助模型推理或私有连接配置。

外部插件默认仅取 choices[0].message.content，不能将 reasoning 字段作为前缀；这属于生成器适配策略，不要求主包依赖 Chat Completions 响应结构。选择第三方端点意味着向该端点发送正文，应由外部插件界面明确配置。受信任宿主插件与外部 HTTP 客户端不是同一权限层；HTTP 对外授权仍需用户明确确认，不因本提案自动开放。

## 实施顺序与验收

先补充生命周期、正文投影和能力探测，再完善标记关联、超时/失败状态与预览。用虚构提供者和本地假接口验证，不将独立生成器打入主包。

验收至少覆盖：首次发送含草稿、不同 N 轮、思考标签残缺、纯正文投影；首请求一次调用、工具续轮零调用、同轮重试复用；并发预览/发送、取消与迟到结果；切换预设/历史编辑/热重载后失效；前缀冲突、不支持协议时零调用；超时停止与显式回退；Raw 与实际注入一致；导出及日志无缓存结果或凭据。保持已有静态前缀、普通动态模板和工具后前缀行为兼容。
