# Raw 预览的完整工具信息与简洁 JSON 界面

Status: proposed

## 问题

用户要求 Raw 预览也能看到完整的工具情况。只展示 messages 或工具名称，无法判断工具定义是否发送、开关是否生效、工具调用参数与结果是否完整，以及预填充兼容转换实际做了什么。

这是对预览能力的要求。已在 next-ver 核对现状：Raw 视图渲染的是该次请求捕获的完整 JSON 快照（web/request-preview.js 对 current.raw 做 jsonTree），tools 字段随 provider、model、messages、system 等一起进入快照（src/lib/request-preview.mts），因此工具定义并非整体缺失；消息预览视图不含工具调用与结果的专门呈现，也没有“工具情况”摘要或原生/DSML 转换的区分。具体的界面缺口与默认展开层级仍需按下面各项逐条核对。

用户补充：现有折叠方式操作繁琐，应采用更简洁的 JSON 结构化 UI，减少为了查看一个字段而连续展开多层的操作。本次只记录 Note，不实施界面修改。

## 方案

Raw 的主视图展示所选请求的完整 JSON 请求体，工具字段与消息字段同等可见、可折叠、可复制。必须使用该次请求捕获的不可变快照，不能从当前工具面板重新拼接历史请求。

### 展示范围

- 实际发送的工具目录：工具名称、说明、完整参数 schema 及协议支持的其他字段，不只列名称。
- 工具控制参数：例如 tools、tool_choice、parallel_tool_calls；字段不存在时如需解释，应明确显示“未发送”，不编造默认值写入 Raw。
- 请求历史中的工具调用：调用 ID、名称、参数、工具结果及其对应关系，保留协议原有结构。Chat 的 tool_calls/tool_call_id 与 Messages 的 tool_use/tool_result 均需可查。
- 工具续轮：每次请求分别查看当时发送的定义、调用历史与结果，不能仅显示第一轮或把后续轮次混入前一轮。

尚未发生的模型调用和工具结果不属于当前请求 Raw。只有后续请求实际携带这些内容时，才在对应请求快照中出现；如增加响应调试信息，应独立标识来源。

### 预填充与工具兼容转换

启用 DSML 转换时，原生 tools 可能已被移除，工具定义及历史可能转入提示词文本。Raw 必须展示转换后的实际形态，不能为了看起来完整而补回原生字段。

可在 JSON 旁增加“工具情况”摘要，标明原生工具、DSML 转换、移除或未捕获。若展示转换前定义，使用明确分开的只读区域，并与相同请求身份绑定；不能标成实际发送字段，也不能影响复制原始 JSON。

工具被禁用后的“当前可用工具”与“历史已经调用过的工具”是不同概念。不能仅因工具现在停用就隐藏该次请求实际携带的历史调用或结果。

### 简洁的 JSON 结构化界面

采用紧凑的代码树样式：缩进、括号、键名和值直接呈现，用小箭头控制对象和数组展开，不为每一层增加独立卡片或冗长的“对象/数组/字符串”说明。

- 默认展示顶层字段，并展开足以辨认消息和工具条目的浅层结构；深层 schema 与大结果按需展开，避免默认全折叠。
- 折叠行显示简短内容摘要和条目数量，消息可看到角色，工具可看到名称；这些只是 UI 提示，不改变 JSON 本身。
- 普通字符串直接展示，长文本提供就地展开/收起，不再套一层必须点击的“字符串”节点。保留换行可读性与完整内容访问。
- 提供简洁的批量展开/收起入口，大数据分批渲染，避免一次展开导致卡顿。
- 保留完整复制按钮；显示摘要、折叠和截短均不能改变复制得到的原始请求。
- 控件支持键盘操作，浅色和深色主题下键名、值与折叠状态易于辨认。

不要求引入大型 JSON 编辑器或可写功能。具体默认展开层级通过消息、工具和长结果样例验证，以减少操作为准。

### 性能与边界

沿用结构化 JSON 的按需展开与分批渲染。大 schema、长工具结果、嵌套内容可默认折叠，但不能悄悄截断复制内容。遇到快照大小限制、清理或捕获失败，应标记不完整/不可用，不能声称完整。

预览只读取快照，不刷新工具目录、不执行工具、不重新运行动态解析器。草稿、适配器输入与实际出站仍明确区分；认证头和 API 密钥不属于 Raw 请求体展示范围。

## 考虑过的替代方案

**只增加工具名称列表。** 无法检查 schema、调用参数、结果或选择策略，不满足完整调试需求。

**用当前工具面板补齐。** 当前配置可能已改变，会让历史预览与实际发送不一致。

**把转换前工具重新塞进 Raw。** 会误导用户认为接口实际收到了原生 tools；转换前信息只能独立展示。

## 验收与风险

- 打开 Raw 后可直接识别顶层参数、消息角色与工具名称，不必逐个展开所有外层包装。
- 键值紧凑展示，长文本可就地展开，批量折叠操作可用；保持完整工具信息和原始复制行为。

- 使用包含嵌套 schema、工具选择参数和历史调用/结果的虚构请求，确认字段可展开且复制内容与捕获请求体一致。
- Chat、Messages、DSML 转换和移除工具四类路径分别核对；未发送字段不伪造，转换后工具提示词可查。
- 同一会话修改工具策略后，旧快照保持不变，新请求反映新策略。
- 多轮工具调用切换快照时定义、参数和结果不串轮；历史调用与当前工具启用状态不混淆。
- 大工具目录和长结果保持按需渲染，查看与复制均不触发模型或工具调用。
- 超过快照限制或捕获失败时显示真实状态，不以残缺内容冒充完整 Raw。

本次仅记录需求和验收标准，未修改运行时代码或执行接口调用。核对现状只读了 next-ver 的 src/lib/request-preview.mts 与 web/request-preview.js。
